# AI 연결 설정과 오른쪽 채팅 사이드바

## 변경과 이유
사용자 요청 4건을 반영했다. 설정에 CLI 설치/로그인/재확인/계정 표시를 추가하고, 기존 AI 팝업을 오른쪽 분할 채팅 패널로 교체했다. 결과 저장 위치는 전송 시 선택된 실제 폴더로 고정하고, 목록 선택은 제거 가능한 첨부 썸네일로 연결했다.

jena-note의 AIChatViewController, AIChatTranscriptView, AISettingsViewController 및 채팅 레이아웃 기록을 직접 확인해 대화 배치·가변 폭·하단 입력 구조를 가져왔다. 채팅에는 요청·결과 이미지·오류가 각각 남고, 결과 이미지는 다음 요청의 참조로 첨부한다.

## 결정과 절충
- 기존 기본 CLI인 Codex를 연결 대상으로 했다. PATH뿐 아니라 nvm 등 사용자 설치 경로도 탐색한다.
- 공식 App Server initialize → account/read로 계정을 조회한다. 계정 파일/토큰을 직접 읽거나 복제하지 않는다. 실제 계정 정보는 검증 로그에 넣지 않았다.
- 설치/로그인은 버튼에서 Terminal로 이어진다. 자동 재설치나 로그인 변경은 실행하지 않았다.
- 가상 목록에서는 이전 폴더로 몰래 저장하지 않고 폴더 선택을 안내한다. 생성 중 폴더 변경은 진행 중인 요청에 영향을 주지 않는다.
- 패널을 접어도 입력/대화/생성 작업은 유지한다. 앱 재시작 후 대화 복원은 포함하지 않는다.
- CLI가 종료 요청에 응답하지 않을 때 2초 후 해당 프로세스를 종료하도록 보완했다. 원격 작업/모든 자식 프로세스 종료를 보장하지 않는다.

## 검증 및 발견
- 실제 설치된 codex-cli 0.157.0에서 실행 파일 탐색·계정 조회 성공. 로그는 상태와 계정 정보 존재 여부만 기록했다.
- 계정 조회 fixture는 미설치, 디렉터리 거부, ChatGPT 계정, 로그아웃, API 키, 프로토콜 실패, 무응답 제한 시간을 검증한다.
- 생성 서비스는 기존 PNG/원본 보존 검사와 종료 신호를 무시하는 CLI 취소를 검증한다.
- 목록의 프로그램적 새로고침/선택 복원은 사용자 선택 이벤트에서 제외해, 제거한 첨부가 되살아나지 않도록 했다.
- UI는 오른쪽 패널, 접기/열기, 중앙 뷰어 전환, 선택→썸네일→제거, 재선택, 텍스트 전체 선택/메뉴, 가상 목록 저장 차단, 연결 상태별 설치/로그인/재확인 버튼을 검증한다.
- UI에서 테스트용 CLI로 파일을 실제 저장하며 생성 중 폴더 변경이 저장 목적지를 바꾸지 않는지 확인한다.
- 초기 계정 fixture의 셸 문자열 비교가 JSON의 슬래시 이스케이프를 고려하지 못해 실패했다. 필수 refreshToken 필드와 실제 요청-응답 순서를 검증하도록 수정했다.
- AppKit의 프로그램적 selectItems 호출은 사용자 선택 delegate를 발생시키지 않는다. UI 테스트는 선택 상태와 사용자 선택 delegate 이벤트를 함께 전달해 실제 이벤트 경로를 검증한다.
- 실제 유료 이미지 생성 및 실제 설치/로그인 변경은 실행하지 않았다.

최종 실행 결과는 `test/AI_사이드바_2026-10-28/`에 보존한다.

최종 결과: 빌드 성공, 서비스 테스트 60개·UI 테스트 36개 통과, diff 검사 통과. 실제 Codex 계정 조회 성공.

## 생성 결과 표시 후속 수정
- 저장 완료 메시지에 폴더 경로 대신 결과 파일명을 표시한다.
- 저장된 이미지 보기 버튼은 MainWindowController의 기존 상세 열기 흐름을 사용한다. 여러 결과는 같은 상세 목록에 전달하며 AI 패널과 기존 탐색 위치는 유지한다.
- 결과 파일이 모두 이동/삭제되었으면 안내한다.
- 기존 UI 통합 시나리오에 파일명 표시와 실제 버튼 클릭 → 앱 상세 전환 검증을 추가했다.

후속 검증: make build 성공, UI 테스트 36개 통과, git diff --check 통과. 로그: result-viewer-build.log / result-viewer-ui-tests.log.

## 통합 입력창 후속 수정
사용자 제공 대화 샘플을 기준으로 대화 배경을 투명하게 통일하고 하단의 한 입력창에 조작을 모았다. + 이미지 추가, ⋯ 설정/저장 위치 확인, 진행 표시와 중지 아이콘을 제공한다. 썸네일은 입력창 바로 위에 유지한다.

AIChatInputView에서 Enter를 전송으로 처리하되 Shift+Enter는 개행, 한글 조합 중 Enter는 NSTextView에 위임한다. placeholder와 입력 높이 자동 조절을 추가했다. 추가 요청에 따라 모델 선택을 같은 입력창에 포함했다. 선택값은 앱 설정에 저장하고 Codex exec의 --model 인자로 전달한다. 기본 모델 선택 시 인자를 생략해 CLI 설정을 따른다. 음성 라이브는 추가하지 않았다.

검증: Enter가 실제 생성 흐름을 호출하는 UI 통합 검증, Shift+Enter/IME/입력 잠금 테스트, 투명 배경과 입력창 내 조작 배치, 긴 입력 높이 제한, 밝은/어두운 테마 캡처.


모델 목록: 버튼을 열 때 `model/list`를 조회해 CLI/계정 변경을 반영한다. 페이지를 합치고 숨김·이미지 입력 미지원·중복 항목을 제외한다. 구형 응답의 누락된 inputModalities는 이미지 지원으로 처리한다. 조회 실패 시 기본 모델로 복귀할 수 있고 다음 클릭으로 재시도한다. 모델 선택은 Codex 요청 처리 모델이며 이미지 생성 도구 내부 모델을 변경하는 설정은 아니다.


최종 검증: make build 및 git diff --check 성공. 서비스 테스트 62개, UI 테스트 37개 통과. 설치된 Codex의 실제 model/list 조회에서 6개 모델 수신. 밝은/어두운 테마 캡처를 확인했다. 생성은 fixture로 요청 모델 전달·저장·상세 열기까지 검증했으며 실제 이미지 생성 요청은 실행하지 않았다. 기록: test/AI_사이드바_2026-10-28/ai-composer-*.log, ai-model-probe.log, ai-sidebar-*.png.


## 생성 대기 표시 후속 수정
요청에 따라 + 버튼과 파일 선택 액션을 제거했다. 생성 진행 아이콘을 대화 마지막으로 이동하고 “이미지를 만들고 있어요..”를 함께 표시한다. 표시 전환 때 대화 높이를 다시 계산해 최초 요청에서도 즉시 나타나고 자동 스크롤한다. 성공·실패·취소는 공통 종료 경로에서 표시를 제거한다. UI 검증에 버튼 제거, 진행 문구·아이콘 위치, 성공·실패 시 제거를 추가했다.

검증: make build 성공, UI 테스트 37개 및 git diff --check 통과. 로그: ai-loading-build.log / ai-loading-ui-tests.log.


## 헤더 겹침 수정
fullSizeContentView 창에서 AI 내부 스택의 상단을 view.topAnchor에 고정해 툴바 뒤에 제목이 가려졌다. 기존 목록·좌측 사이드바처럼 safeAreaLayoutGuide.topAnchor를 기준으로 배치한다. 툴바 버튼 위치를 옮기지 않고 채팅 콘텐츠가 헤더 아래에서 시작하게 했다. UI 회귀 검증은 목록/상세 모드 각각 940×500, 1200×800 창에서 제목·닫기 버튼의 실제 창 좌표가 contentLayoutRect 안에 있는지 확인한다.

검증: make build 성공, UI 테스트 38개 및 git diff --check 통과. 기록: ai-header-build.log / ai-header-ui-tests.log.


## 하단 사용 현황
CLI 사용량 조회를 연결해 입력창 아래에 한도별 사용 비율과 리셋 카운트다운을 표시했다. 24시간을 기준으로 d/h와 h/m을 전환하며 지난 시각은 0h 0m이다. 표시 시, 생성 종료 후 및 표시 중 1분마다 갱신한다. 조회 실패 시 이전 비율을 지우고 확인 불가로 표시한다. 사용량은 계정 전체 한도이며 앱 단독 사용량으로 표현하지 않는다. 서비스 검증에 RPC 요청·파싱과 시간 경계를, UI 검증에 하단 배치·조회 성공/실패를 추가했다.

검증: 빌드 성공, 서비스 64개/UI 38개 테스트 통과. 실제 CLI 사용량 1개 한도 및 리셋 시각 조회 성공. 기록: test/AI_사이드바_2026-10-28/ai-usage-*.log.


## 사용 현황 수동 재조회
사용 현황 오른쪽에 arrow.clockwise 아이콘을 추가하고 기존 조회 흐름에 연결했다. 조회 중 중복 클릭 방지와 종료 후 버튼 복구를 적용했다. UI 검증에 실제 버튼 클릭 → 재조회 → 변경된 비율 반영, 조회 중 잠금 및 실패 후 복구를 추가했다.

검증: 빌드 성공, UI 테스트 38개 및 git diff --check 통과. 기록: ai-usage-refresh-build.log / ai-usage-refresh-ui-tests.log.
