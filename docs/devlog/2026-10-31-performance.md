# 성능 개선과 재귀 탐색 대기 화면

## 요청과 변경

앞선 리뷰의 6개 항목을 순서대로 구현했다.

1. 전체 목록의 메모리 캐시 스탬프 조회를 메인 스레드에서 제거했다.
2. 그리드의 비율 조회를 생략하고 유효한 썸네일 비율을 재사용한다. masonry 전체 재배치는 50ms에서 150ms 간격으로 합친다.
3. 썸네일 표시와 HEIC 저장을 분리하고 저장 대기 슬롯을 16개로 제한했다. 초과 저장은 버리지 않고 워커에서 대기한다.
4. 원본 로딩 취소를 내부 Task까지 전달하고 한 번에 한 장만 디코딩한다.
5. 색상 보정 미리보기는 백그라운드에서 최대 1600px로 처리한다. 적용은 원본 크기를 유지한다. 도구 전환·리셋·창 닫기 때 오래된 미리보기를 취소한다.
6. 사이드바 폴더 집계는 상위·하위 요청을 합치고 무효화된 탐색을 중단한다.

## 재귀 탐색 문제

기존 코드는 클릭 직후 빈 목록을 표시하고 모든 하위 폴더 열거와 정렬이 끝나야 실제 목록을 표시했다. 그동안 빈 폴더 문구가 떠 이미지가 없는 것처럼 보였다.

이제 클릭 직후 진행 표시와 ‘이미지를 찾는 중…’ 문구를 표시한다. 탐색 중 최대 64장의 첫 묶음과 발견 개수를 보여주고, 완료 시 최종 정렬과 선택 복원을 수행한다. 실제 빈 폴더 문구는 완료 후에만 표시한다. 폴더 전환·창 닫기 때 탐색을 취소하고, 탐색 중 뷰어로 이동했다가 돌아오면 전체 목록 탐색을 재개한다.
