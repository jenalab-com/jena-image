# 2026-10-18 — 뷰어 툴바 "세로 맞춤" · "가로 맞춤" 추가

## 요청·배경
상세(뷰어) 화면 상단 줌 아이콘 옆에 두 개를 더 — 세로로 꽉 차게, 가로로 꽉 차게.
기존 "화면에 맞춤"은 긴 변 기준으로 전체가 들어오게 축소만 해서(1.0 상한), 세로로 긴 이미지를 폭에 맞춰 읽거나 가로 패노라마를 높이에 맞춰 보는 용도엔 부족했다.

## 변경 사항
- [Sources/viewer/ImageDisplayView.swift](../../Sources/viewer/ImageDisplayView.swift)
  - `isFitMode: Bool` → `fitMode: FitMode(none/window/height/width)`. 기존 `isFitMode`는 계산 프로퍼티로 남겨 호출처 무변경.
  - `fitHeight()` / `fitWidth()` 추가. 한 축을 `contentSize`에 맞추고 배율은 `[0.1, 5.0]`으로 클램프. 작은 이미지도 꽉 채우도록 **확대 허용**(기존 fitToView와 다름).
  - 넘치는 축의 시작점: 세로 맞춤은 왼쪽 끝, 가로 맞춤은 **위쪽**(읽는 순서). 짧은 축은 `CenteringClipView`가 가운데 정렬.
  - 창 크기 변경·회전·플립 뒤 재적용은 `reapplyFit()`이 현재 모드대로 — 기존 `fitToView()` 직접 호출 3곳 교체.
- [Sources/viewer/ViewerViewController.swift](../../Sources/viewer/ViewerViewController.swift): `zoomFitHeight()` / `zoomFitWidth()` 통과.
- [Sources/app/MainWindowController.swift](../../Sources/app/MainWindowController.swift): `ToolbarID.zoomFitHeight/zoomFitWidth`, `updateToolbarState` 뷰어 모드 활성 목록.
- [Sources/app/MainWindowController+Delegates.swift](../../Sources/app/MainWindowController+Delegates.swift): 기본 아이템 순서(맞춤 뒤), 아이콘 `arrow.up.and.down` / `arrow.left.and.right`.
- [Sources/app/MainWindowController+Actions.swift](../../Sources/app/MainWindowController+Actions.swift): 액션 2개, `validateUserInterfaceItem` 뷰어 전용 목록.
- [Sources/app/MainMenu.swift](../../Sources/app/MainMenu.swift): 보기 메뉴 "화면에 맞춤" 아래 2항목(단축키 없음 — ⌘0·⌘9와 충돌 피함).
- [Sources/services/Localization.swift](../../Sources/services/Localization.swift): `fitHeight` / `fitWidth` 4개 언어.

## 검증
- `make build` 에러 0.
- 수동(사용자 확인 필요): 뷰어에서 세로 긴 이미지 → 가로 맞춤 시 폭이 꽉 차고 위부터 보이는지 · 가로 긴 이미지 → 세로 맞춤 시 높이가 꽉 차고 왼쪽부터 보이는지 · 창 크기 바꿔도 유지되는지 · 브라우저 모드에선 두 아이콘이 비활성인지.

## 트레이드오프
- 확대 허용이라 아주 작은 이미지는 흐려 보일 수 있다. 그게 "꽉 차게"의 뜻이라 의도된 동작. 원하면 fitToView처럼 1.0 상한을 둘 수 있음.
- 툴바 아이콘이 6개로 늘어 좁은 창에서는 오버플로 메뉴로 밀릴 수 있다(`displayMode = .iconOnly`라 여유는 있음).

# 2026-10-18 (추가) — 맞춤 셋을 토글 그룹으로, 모드 유지

## 요청·배경
전체·세로·가로 맞춤 중 하나만 켜지는 토글로. 켜진 모드는 다음 이미지에도 계속 적용. 기본은 전체 맞춤.

## 변경 사항
- [Sources/services/AppSettings.swift](../../Sources/services/AppSettings.swift): `ViewerFitMode(window/height/width)` + `viewerFitMode`(UserDefaults, 기본 `.window`). 앱을 다시 켜도 유지.
- [Sources/viewer/ImageDisplayView.swift](../../Sources/viewer/ImageDisplayView.swift): `display(_:)`가 `fitToView()` 고정 대신 `applyFit(AppSettings.shared.viewerFitMode)`.
- [Sources/viewer/ViewerViewController.swift](../../Sources/viewer/ViewerViewController.swift): `applyFitMode(_:)` 하나로 통합(`zoomFitHeight/Width` 제거).
- [Sources/app/MainWindowController+Actions.swift](../../Sources/app/MainWindowController+Actions.swift): 세 액션 → `selectFitMode(_:)`(설정 저장 → 툴바 선택 동기화 → 뷰어면 즉시 적용). `validateMenuItem`에서 보기 메뉴 세 항목에 라디오 체크.
- [Sources/app/MainWindowController+Delegates.swift](../../Sources/app/MainWindowController+Delegates.swift): `toolbarSelectableItemIdentifiers`로 셋을 선택 그룹에 등록 — AppKit이 하나만 눌린 모양으로 그린다.
- [Sources/app/MainWindowController.swift](../../Sources/app/MainWindowController.swift): 툴바 생성 직후 `syncFitModeSelection()`으로 저장된 모드 반영.

## 동작 흐름
- 토글은 브라우저 모드에서도 눌려 설정만 바뀌고(아이템은 비활성이라 실제론 뷰어에서만), 뷰어에선 즉시 적용.
- 확대/축소/원본 크기는 **현재 이미지에만** 수동 배율을 주고 토글은 그대로 켜져 있다. 다음 이미지로 넘어가면 다시 토글 모드로 연다.

## 검증
- `make build` 에러 0.
- 수동(사용자 확인): 가로 맞춤 켜고 ←→로 넘겨도 계속 가로 맞춤인지 · 셋 중 하나만 눌린 모양인지 · 보기 메뉴에 체크가 따라오는지 · 앱 재시작 후 유지되는지 · 첫 실행 기본이 전체 맞춤인지.

## 트레이드오프
- 수동 줌 뒤에도 토글이 켜진 채라 "지금 화면은 토글과 다른 배율"인 순간이 있다. 토글을 모드 선언으로 보면 자연스럽고, 끄려면 다른 토글을 누르면 된다.

# 2026-10-18 (추가 2) — 맞춤 아이콘 크기·강조 표시 · 세로/가로 맞춤 가운데 정렬

## 요청·배경
화살표 아이콘이 돋보기보다 커 보임. 셋을 돋보기처럼 나란한 버튼 디자인으로. 세로/가로 맞춤 시 왼쪽·아래로 붙는 버그.

## 시도와 결론
- `SymbolConfiguration(scale:)`은 툴바가 심볼 이미지에 자기 크기를 다시 입혀서 무효. → 심볼을 **16×15 고정 비트맵**에 10pt 보통 굵기로 그려 넣음(`fitSymbol`). 11pt는 크고 9pt는 작았음.
- `toolbarSelectableItemIdentifiers`는 선택 가능 아이템마다 베젤이 생겨 간격이 벌어짐 → 폐기.
- `NSToolbarItemGroup`(세그먼트)로 두 묶음 모두 만들어 보니 모양이 같아지긴 하나 보기 싫고, 묶음 `isEnabled`가 칸에 전파되지 않아 비활성으로 보임 → 폐기.
- 최종: 돋보기와 같은 일반 아이템 3개. **켜진 모드는 심볼을 강조색으로 칠한 비트맵**(`isTemplate = false`)으로 교체해 표시. `syncFitModeSelection()`이 세 아이템 이미지를 다시 그린다.

## 가운데 정렬
- `centerVisibleRect()`: 넘치는 축은 `(doc - visible)/2`로 스크롤. 보이는 크기는 배율 변경 직후 `clipView.bounds`가 옛 값일 수 있어 `contentSize / magnification`으로 계산.
- 원점을 0으로 클램프하면 짧은 축이 아래/왼쪽에 붙는다(가로 긴 그림의 가로 맞춤). 클램프를 빼서 음수 원점을 넘기면 `CenteringClipView`가 가운데에 놓는다.

## 검증
- `make build` 에러 0. 사용자 스크린샷 확인: 아이콘 크기 OK, 세로·가로 맞춤 가운데 OK.
