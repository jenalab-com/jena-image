## 구현 상태

이미지 생성은 MainWindowController+AI → AIImageWindowController → AIImageGenerationService → 외부 CLI → PNG 검증/복사 흐름이다. Codex 또는 request.json 계약을 받는 사용자 지정 실행 파일을 지원한다. 모델과 인증은 외부 CLI가 소유하며, 앱에 직접 이미지 생성 API나 계정 설정은 없다.

유사 이미지 검색은 ImageSimilarityService의 Apple Vision feature print revision 2를 이용한다. 현재 목록을 대상으로 로컬 분석하며, 분석 결과를 캐시하고 거리순 최대 100개를 반환한다.

## 발견 및 우선순위

1. **실제 생성 연결 검증 공백**: 기존 AI 성공 테스트는 참조 PNG를 복사하는 fixture다(Tests/AIImageGenerationTests.swift:32). CLI 호출/파일 저장은 검증하지만 모델이 새 이미지를 생성하는지는 검증하지 않는다. Codex 이미지 생성 도구의 실제 가용성은 미확인이다. 출시 완료 판정 전 실제 연결로 설명만 생성/참조 생성 각 1회가 필요하다.
2. **P2 — 취소 후 작업 잠금이 풀리지 않을 수 있음(정적 분석)**: 서비스는 Process.terminate()를 한 번 요청하고 waitUntilExit()로 무기한 대기한다(Sources/ai/AIImageGenerationService.swift:56,134). CLI가 종료 신호를 무시하거나 종료 처리가 멈추면 UI는 취소 버튼을 비활성화한 채 창 닫기도 막는다(AIImageWindowController.swift:214,236). 종료 유예 시간 이후의 복구 수단이 없다. 기존 취소 테스트는 exec sleep만 사용해 이 조건을 검증하지 않는다.
3. **P2 — 실패 후 이전 결과가 남음(정적 분석)**: 성공 시 savedURLs/preview를 갱신하지만 다음 요청 시작/실패에서 초기화하지 않는다(AIImageWindowController.swift:183-210). A 성공 후 B 실패 시 실패 메시지 아래에 A 미리보기와 활성화된 결과 보기 버튼이 남는다. 이전 결과임을 표시하거나 현재 요청 결과와 분리할 필요가 있다.
4. **설치 환경 제약**: 현재 codex-cli 0.157.0은 /Users/sejong_jeromena/.nvm/versions/node/v22.16.0/bin/codex에 있다. /opt/homebrew/bin/codex, /usr/local/bin/codex는 없다. GUI에서 상속받은 PATH에 nvm 경로가 없으면 기본값 codex를 찾지 못한다. 절대 경로 입력으로 우회할 수 있으나 앱 재시작 후 실행 파일 설정을 보존하는 구현은 없다. Finder 실행 환경 자체는 이번에 확인하지 않았다.

## 결정과 절충

요청이 확인 작업이므로 기능 수정이나 실제 생성 요청까지 확장하지 않았다. CLI 옵션은 설치된 codex exec --help와 대조했다. 유사 이미지 검색과 외부 이미지 생성의 검증 수준을 분리했다. 성공/실패 파일 처리 테스트 통과를 실제 AI 생성 성공으로 해석하지 않는다.
