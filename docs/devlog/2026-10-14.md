# 2026-10-14 — 하위 폴더 이미지 포함 보기 토글

## 배경

사이드바에서 폴더를 고르면 그 폴더의 직속 이미지와 하위 폴더 타일만 보였다. 사진이 날짜·주제별 하위 폴더에
흩어져 있을 때 한 번에 훑어볼 수 없어, "선택한 폴더를 루트로 하위 폴더 이미지까지 평면으로" 보여주는 모드를 추가했다.
어느 깊이의 폴더를 선택해도 그 폴더가 기준이 된다.

## 변경 사항

### `Sources/services/AppSettings.swift`
- `recursiveBrowsing: Bool` (키 `browserRecursive`, 기본 off). 재시작 후에도 유지.

### `Sources/services/FileService.swift`
- `recursiveImages(at:sortKey:ascending:)` 추가. `FileManager.enumerator` 깊이 우선 열거, 숨김·패키지 내부 제외,
  정규 파일 중 지원 확장자만 모아 기존 `sortURLs`로 정렬.

### `Sources/sidebar/SidebarViewController.swift`
- 상단 바에 토글 버튼(`square.stack.3d.down.right`)을 새로고침 왼쪽에 배치. 켜짐은 강조색, 툴팁에 상태 표기.
- `SidebarDelegate.sidebar(_:didToggleRecursive:)` 추가.

### `Sources/app/MainWindowController.swift`
- `folderContents(at:)` / `enumerateFolderContents(at:)` 신설 — 모드에 따라 일반 열거 또는 재귀 열거.
  재귀 모드는 `folders: []`로 돌려 폴더 타일을 숨기고 이미지만 평면으로 보인다.
- `navigateToFolder`, `refreshAfterExternalChange`, `imageFilesInCurrentFolder`가 모두 이 헬퍼를 쓴다
  → 뷰어의 좌우 탐색·썸네일 스트립도 재귀 목록을 따른다.

### `Sources/app/MainWindowController+Delegates.swift`
- 토글 시: 브라우저면 현재 폴더 재로드, 뷰어면 현재 이미지를 유지한 채 탐색 목록만 교체, 북마크 뷰면 무시.

## 결정 사항

- **폴더 타일은 재귀 모드에서 숨김**: 하위 폴더 이미지가 이미 다 보이므로 폴더 타일은 중복. 트리 이동은 사이드바가 담당.
- **파일 이름은 그대로**: 서로 다른 하위 폴더에 같은 이름이 있을 수 있지만 상대 경로 접두는 셀을 어지럽혀 보류.
  필요해지면 툴팁에 상대 경로를 넣는 쪽이 먼저.
- **파일시스템 감시는 확장하지 않음**: 재귀 모드라도 감시 대상은 기존 규칙(루트+현재+펼친 폴더). 깊은 하위 폴더 변경은
  새로고침(⌘⇧R)으로 반영. 수천 폴더를 전부 감시하면 디스크립터 한도(256)를 넘기 때문.
- 정렬은 전체 평면 목록에 한 번 적용(폴더별 묶음이 아님). 이름순이면 폴더 경계 없이 섞인다.

## 수동 GUI 검증 체크리스트

1. 사이드바 상단, 새로고침 왼쪽에 토글 버튼 표시. 클릭 시 강조색 on/off, 툴팁 상태 변경.
2. on → 하위 폴더가 있는 폴더 선택 → 폴더 타일 없이 모든 깊이의 이미지가 그리드에 표시, 상태바 이미지 수 = 전체 합.
3. on 상태로 하위 폴더 선택 → 그 폴더 기준으로 다시 재귀 목록.
4. 재귀 그리드에서 이미지 더블클릭 → 뷰어 ←/→ 가 재귀 목록 전체를 순회.
5. 뷰어에서 토글 off → 현재 이미지 유지, 썸네일 스트립이 직속 폴더 목록으로 바뀜(현재 이미지가 직속에 없으면 유지).
6. off → 기존과 동일(폴더 타일 + 직속 이미지).
7. 앱 재시작 후 토글 상태 유지.
8. 북마크 뷰에서 토글 → 북마크 그리드가 유지되고 튕기지 않음.

## 빌드 결과

`make build` — 경고·에러 0.

# 2026-10-14 (추가) — 그리드 썸네일 440px + 하위 폴더 포함 보기 경로 줄

## 배경

슬라이더 최대(2.0배)에서 썸네일 영역이 약 220pt까지 커지는데 비트맵은 100pt 요청(200px)으로 만들어져 흐렸다.
또 하위 폴더 포함 보기에선 파일 이름만 보여 어느 폴더의 파일인지 알 수 없었다.

## 변경 사항

### `Sources/browser/BrowserViewController.swift`
- 썸네일 요청 크기 100pt → 220pt(`thumbnailRequestSize`). 생성 시 2배라 긴 변 440px.
- 캐시 조회를 `thumbnail(for:minPixelSize: 440)`으로 — 스트립이 먼저 만든 작은 썸네일이 있으면 큰 크기로 다시 생성.
- `display(folders:images:recursiveRoot:)` — 기준 폴더를 받아 `relativeFolderComponents(of:)`로 셀마다 상대 경로 계산.
- `applyItemSize()` — 셀 높이 = 140 × 배율 + (재귀 모드면 경로 줄 14pt). 글자 크기는 고정이라 경로 줄은 배율 미적용.

### `Sources/services/ThumbnailCache.swift`
- `thumbnail(for:minPixelSize:)` 추가. `store`는 같은 URL에 더 큰 썸네일이 있으면 덮어쓰지 않음(스트립 80×60과 공유하므로).

### `Sources/browser/BrowserItem.swift`
- `pathLabel`(10pt, 보조색, 1줄) 을 썸네일과 파일 이름 사이에 추가. 높이 제약 0/14로 접고 펼침.
- `viewDidLayout`에서 라벨 폭을 재서 문자열 결정: 전체 `a/b/c` → 안 들어가면 `a … c`(폴더 이름 통째 유지) → 그래도 넘치면 가운데 말줄임.
- 툴팁은 상대 경로 전체 + 파일 이름.

### `Sources/app/MainWindowController.swift`
- `navigateToFolder`·`refreshAfterExternalChange`에서 재귀 모드일 때 `recursiveRoot: url` 전달.

## 결정 사항

- 메모리: 440px 썸네일 1장 ≈ 770KB(RGBA). 캐시 한도 500MB면 약 650장. 큰 폴더에선 LRU로 밀려 재생성이 늘지만 체감 가능 수준은 아닐 것으로 봄. 느리면 한도를 올리거나 1GB로.
- 기준 폴더 직속 파일은 경로 줄이 빈 줄로 남음(셀 높이를 모드 단위로 통일해 그리드가 울퉁불퉁해지지 않게).

## 수동 GUI 검증 체크리스트

1. 슬라이더 최대에서 썸네일이 선명한지(이전 대비).
2. 뷰어 스트립을 먼저 본 뒤 브라우저로 돌아와도 그리드 썸네일이 흐리지 않은지(캐시 승격).
3. 하위 폴더 포함 on → 셀마다 이름 위에 회색 경로 줄. 직속 파일은 빈 줄.
4. 깊은 경로(3단 이상)에서 폭이 좁으면 `첫폴더 … 끝폴더`로 접히는지, 슬라이더를 키우면 전체 경로로 펴지는지.
5. 폴더 이름 하나가 셀보다 길면 가운데 말줄임.
6. off로 돌리면 경로 줄이 사라지고 셀 높이가 원래대로.

## 빌드 결과

# 2026-10-14 (추가 2) — 설정 > 썸네일 탭 (최대 크기 · 메모리 한도 · 적용 버튼)

## 변경 사항

- `AppSettings`: `thumbnailMaxPixel`(220/330/440, 기본 440) · `thumbnailCacheMB`(100~2048, 기본 500) · `.thumbnailSettingsApplied` 알림.
- `ThumbnailCache.setMemoryLimit(bytes:)`.
- `BrowserViewController`: 요청 크기·최소 픽셀을 설정에서 읽음.
- `MainWindowController.setupThumbnailSettings`: 시작 시 저장된 한도 반영, "적용" 알림을 받아 한도 갱신 → 캐시 비움 → 브라우저 모드면 현재 폴더 재로드.
- `PreferencesWindowController`: "썸네일" 탭 신설(다국어 탭 라벨 4종). 크기 팝업 + 한도 슬라이더(50MB 단위, 1024 이상은 GB 표기)
  + 안내 문구("한 장 약 NKB 기준 약 N장") + **적용** 버튼. 컨트롤을 움직이면 안내만 즉시 바뀌고, 저장·반영은 적용 때만.
  변경이 없으면 적용 버튼 비활성.

## 결정 사항

- 크기는 숫자 입력이 아니라 3단계 선택: 셀 최대 220pt × 레티나 2배 = 440px가 쓸모 있는 상한이라 그 이상은 의미가 없고,
  캐시의 "이 크기 이상이면 재사용" 규칙이 고정 단계에서 예측 가능하다.
- 실시간 적용 대신 적용 버튼: 캐시 비움 + 전 폴더 재생성이 무거운 작업이라 슬라이더 드래그마다 돌리면 부하.

## 수동 GUI 검증 체크리스트

1. 설정 > 썸네일 탭: 팝업 기본 440px, 슬라이더 500 MB, 안내 "약 774KB 기준 약 661장".
2. 슬라이더를 움직여도 그리드가 바뀌지 않고 안내만 바뀜. 적용 버튼이 활성화됨.
3. 적용 → 그리드 썸네일이 다시 로드됨(잠깐 비었다 채워짐). 버튼은 다시 비활성.
4. 220px로 바꿔 적용 → 슬라이더 최대에서 흐려짐 확인(의도된 동작). 440px로 되돌리면 선명.
5. 앱 재시작 후 두 값이 유지되고, 시작부터 한도가 반영됨.

## 빌드 결과
