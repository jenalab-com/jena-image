# 앱 안에서 업데이트 확인·설치

## 변경
- 앱 메뉴에 **업데이트 확인…**(한·영·일·중)을 추가했다. GitHub 최신 릴리스를 조회해 새 버전이면 변경 내용(Markdown 제목·목록·굵게 정리)과 **설치** 버튼을 보인다. 자동 확인은 하지 않는다.
- 설치: DMG 내려받기(진행률) → 첨부 `digest`(SHA-256)·크기 검증 → 읽기 전용 마운트 → 번들 ID·버전 확인 → 대상 앱과 같은 폴더의 숨김 임시 폴더로 복사·격리 속성 제거 → 마운트 해제 → 교체 스크립트 실행 → 앱 종료. 스크립트는 종료를 기다렸다가 기존 앱을 옆으로 치우고 새 앱을 옮긴 뒤 다시 연다. 옮기기에 실패하면 기존 앱을 되돌려 다시 열고, 60초 안에 종료되지 않으면 아무것도 바꾸지 않고 정리한다.
- App Translocation·읽기 전용 볼륨·쓰기 불가 폴더면 이유를 보이고 다운로드 페이지로 안내한다. 조회 한도·검증 실패 등은 이유와 **다시 시도/다운로드 페이지**를 보인다.
- 확인 주소는 `updateFeedURL` 기본값 설정으로 바꿀 수 있다(검증용, UI 없음). 외부 의존성 없음(URLSession·CryptoKit·hdiutil·ditto·xattr).
- 설계: [app-update-design.md](../app-update-design.md)

## 검증
- 단위 테스트(`Tests/AppUpdateTests.swift`): 버전 비교, 릴리스 파싱·오류, 해시·크기 검증, `file://` 주소로 조회·내려받기·진행률, 설치 가능 판단(번역 위치·실제 읽기 전용 DMG 볼륨·쓰기 불가 폴더), 테스트용 DMG로 마운트·번들 확인·복사·마운트 해제, 잘못된 번들 거부와 흔적 정리, 교체 스크립트 성공·실패 복원.
- UI 테스트(`Tests/UI/UpdateWindowTests.swift`): 최신/새 버전/설치 불가/조회 실패/검증 실패 상태, 설치 순서(내려받기→준비→교체→종료), 설치 버튼이 Enter에 반응하지 않음.
- 실제 앱 종단 검증: 데모 번들 ID로 2.0.0 앱을 임시 폴더에 두고, 2.1.0 DMG와 피드를 로컬 HTTP 서버로 제공. 설치 → 약 5초 뒤 종료·교체·재실행, 설치본 2.1.0·서명 유효·격리 속성 없음·임시 폴더/마운트/스크립트 잔여물 없음. 교체 후 다시 확인하면 "최신 버전". 실제 GitHub API로도 2.0.1 릴리스와 노트 표시 확인(설치는 하지 않음).
- 결과: make build 경고 없음, make test·make test-ui 통과, git diff --check 통과.

## 참고
- 종단 검증 중 "설치"가 클릭 없이 시작된 것처럼 보인 일이 있어 임시 로그를 넣어 확인했다. 트랙패드에서 들어온 실제 클릭(`LMouseUp`, `NSEventSubtypeTouch`, 설치 버튼 위치)이었고 앱 결함은 아니었다. 이를 계기로 설치 버튼을 Enter 기본 버튼에서 뺐다.
- 기존 `종료 신호를 무시하는 CLI도 취소 후 작업을 풀어준다` 테스트가 첫 실행에서 한 번 실패했고 이후 반복 실행에서는 통과했다(시간 의존 흔들림으로 추정, 미확정).
