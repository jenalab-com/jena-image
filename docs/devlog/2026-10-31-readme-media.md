# README 스크린샷·데모 영상과 비교 창 레이아웃 수정

## 변경
- `scripts/media/`에 README·릴리스용 미디어 생성 도구를 추가했다. Unsplash 데모 라이브러리 내려받기(출처 `docs/media/CREDITS.md`), 번들 ID를 분리한 데모 앱 사본, 접근성 API와 합성 마우스 이벤트로 앱을 조작하는 캡처·녹화 스크립트, GIF/MP4 변환으로 구성된다. 사용법은 `docs/media/README.md`.
- README의 Screenshots 섹션을 스크린샷 8장과 데모 GIF 4편(탐색, 유사 이미지, 비교, AI 생성)으로 채웠다. 릴리스 첨부용 MP4는 `.build/media/`에 만든다(저장소 제외).
- 비교 창 버그 수정: 이미지 칸이 높이 0으로 접히고 "줌·팬 동기화" 체크박스가 세로로 늘어나 창 가운데에 떠 있었다. 칸 크기를 맞추면서 낮춘 칸의 세로 압축 저항(250)과 체크박스의 기본 세로 hugging(250)이 같아, 엔진이 토글을 늘리는 해를 골랐다. 토글의 세로 hugging을 required로 올렸다.

## 검증
- 비교 창 레이아웃 UI 테스트(`Tests/UI/CompareLayoutTests.swift`)를 먼저 추가해 실패(토글 526pt, 그리드 20pt)를 확인한 뒤 수정했다. 실제 앱에서 2장·3장 비교 화면을 캡처해 확인했다.
- make build 성공, UI 테스트 62개·단위 테스트 66개 통과, git diff --check 통과.
- AI 이미지 생성을 실제 Codex 계정으로 처음 확인했다. 참조 1장과 한국어 프롬프트로 약 109초 만에 `landscape-08_AI.png`(1535×1025)가 저장되고 채팅·목록에 표시됐다.

## 남은 확인
- 데모 앱(새 번들 ID)으로 처음 생성할 때 "JenaImage이(가) 문서 폴더의 파일에 접근하려고 합니다" 권한 요청이 떴다. 저장 위치는 사진 폴더라서, Codex 하위 프로세스가 `~/Documents`를 읽어 앱 이름으로 요청이 뜬 것으로 추정한다. 새 사용자가 첫 생성에서 같은 요청을 볼 수 있으니 원인 확인이 필요하다.
- 상세 뷰어 우측 썸네일 목록의 맨 위 항목이 툴바 버튼 아래로 겹쳐 보인다. 투명 툴바 의도인지 확인이 필요하다.
