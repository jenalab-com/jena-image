# 2026-10-25 — 다중 이미지 카테고리

## 요청·결정

폴더 위치와 별도로 이미지를 수집하는 카테고리를 추가했다. 한 이미지의 여러 카테고리 지정은
사용자 확인을 받았다. 기획·구조·화면 결정은 `docs/category-design.md`에 기록했다.
기존 북마크와 독립된 경로 기반 저장소를 선택해 원본과 기존 사용자 데이터를 보존한다.

## 변경

- `ImageCategory`, `CategoryStore`: 이름 검증, 중복 없는 다중 지정, 저장/복원, 변경 알림,
  파일/폴더 경로 갱신, 명시적 원본 삭제 반영. 읽기 실패 시 저장 거절.
- 사이드바: 폴더/카테고리 아이콘 전환, 카테고리 행과 이미지 수, 이름 입력 추가, 빈 상태 안내.
- 목록: 폴더·북마크·카테고리에서 지정 체크 메뉴, 다중 선택의 부분 체크, 원본을 남기는 분류 해제.
- 상세: 카테고리 버튼과 공통 지정 메뉴. 상세에서 지정 변경 시 화면을 유지하고 복귀 때 재조회.
- 이동·이름변경 성공 시 카테고리 경로 갱신. 폴더 열거 세대 번호로 다른 화면의 비동기 덮어쓰기 방지.
- 가상 카테고리 보기에서는 이전 폴더로 파일을 붙여넣지 못하도록 비활성화.

## 검증

- 임시 BUILD_DIR에 앱 빌드. 기존 `.build`, 설치 앱과 실행 중인 앱은 교체하지 않는다.
- `make build`: 최종 빌드 성공, 컴파일 경고·오류 없음.
- `make test`: 기존 26개 + 카테고리 저장소 9개 모두 통과.
- `make test-ui`: 카테고리 화면 연결 회귀 테스트 9개 모두 통과(총 44개). 테스트 전용 메모리 썸네일 공급자를 링크해
  사용자 썸네일 디스크 캐시에 접근하지 않는다. 임시 원본과 별도 UserDefaults만 사용한다.
- 실제 사용자 환경의 마우스 조작과 시각적 최종 확인은 별도다.
- `git diff --check` 통과. 확인용 앱: `/tmp/jena-image-categories.1BPqL2/JenaImage.app`.

이번 범위에 포함하지 않았다. 원본 누락 시 자동 정리하지 않는다.
