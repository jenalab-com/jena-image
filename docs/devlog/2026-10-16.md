## 변경 (문서만, 코드 변경 없음)
- **DiskStore 락 범위** — 초안은 HEIC 디코드·인코드·GC(디렉터리 전체 열거)를 모두 락 안에서 했다. 워커 8개가 디스크 계층에서 직렬화되고, `limitBytes` setter가 메인 스레드에서 GC를 동기 실행해 2GB(약 3만 파일)면 슬라이더 조작 중 UI가 1~2초 멈춘다. 락은 카운터만, GC는 utility 직렬 큐에 비동기로 걸기만 하도록 바꿨다. `clear()`는 디렉터리를 옆으로 옮겨 즉시 0으로, 실제 삭제는 GC 큐에서. 테스트 2개를 `waitUntil`로, "setter가 호출자를 막지 않음" 테스트 1개 추가.
- **같은 우선순위 LIFO → FIFO** — `didEndDisplaying` 취소 덕에 visible 큐엔 보이는 셀만 남고, 선로드도 새 선로드 때 전부 취소하므로 LIFO의 이득이 없다. 첫 화면이 아래→위로 채워지는 부작용만 있었다. 스펙 §1.2·§5.1도 갱신.
- **스켈레톤 동기화** — `beginTime = 0`은 CA가 add 시점으로 치환해 동기화되지 않는다. `1`(고정 상수)로.
- **Scheduler `cancel()` 누수** — 완료된 토큰을 취소하면 `cancelled` Set에 영원히 남았다. `running` 집합을 두고 실행 중일 때만 표시. 테스트 추가.
- **`finish` 저장 순서** — `cancelAllPending()` 뒤 도착한 결과를 버리지 않고 메모리 캐시에는 넣는다.
- **실패·미다운로드 자리표시 `hasThumbnail = true`** — 셀이 다시 보일 때마다 재요청해 스켈레톤→심볼로 깜빡이던 것 제거.
- **스파이크(Task 0)** — QuickLook 소요 시간도 측정. 2초를 넘기면 전용 워커 분리를 검토.
- **워커 수 테스트** — `peak == 2`를 `peak <= 2`로(상한 검증이 의도).
- 설정 탭(Task 8) — GC가 비동기라 1초 뒤 사용량 라벨 재갱신.

## 반영하지 않은 것
- `generate` 클로저를 CGImage 반환으로 바꿔 NSImage↔CGImage 왕복을 아끼는 것. Task 2·7의 테스트·`+App.swift`·DiskStore 연결까지 네 군데가 바뀌는 데 비해 이득(장당 변환 1회)이 작아 보류. 구현 중 프로파일에서 잡히면 그때.

## 빌드 때 확인할 것

- `make test`는 톱레벨 코드 방식이라 진입 파일명이 반드시 `Tests/main.swift`.

# 2026-10-16 (추가) — Task 2: ThumbnailProvider (메모리 계층 + 생성 큐 + 중복 합치기 + iCloud 판별 + QuickLook)

## 변경
- `Sources/services/ThumbnailProvider.swift` 신설 — `@MainActor`. 메모리 적중은 동기 완료(토큰 nil), 미적중은 `(url, level)` 키로 in-flight 합치기 → Scheduler → 워커에서 `produce` → 메인 `finish`. 실패는 `(path|mtime)`으로 세션 내 기억. iCloud 비워진 파일은 `isEvictedICloudItem`(새 URL 인스턴스로 읽음)로 판별, visible이면 QuickLook `.thumbnail`, 아니면 `.notDownloaded`. `CGImageSource`·`NSImage(contentsOf:)`는 비워진 파일에 절대 닿지 않는다.
- `Sources/services/ThumbnailProvider+App.swift` — `shared`(워커 = 코어-1, 2~8 → 이 Mac 8), `useQuickLookForEvicted = true`.

- `Tests/ThumbnailProviderTests.swift` 7개, `Tests/main.swift`에 `MainActor.assumeIsolated { runProviderTests() }`.

## 검토에서 고친 것
- **선로드→visible 승격 시 재디코딩** — 계획은 `cancel` + 재등록이었다. 그 항목이 이미 워커에서 디코딩 중이면 결과를 버리고 처음부터 다시 하게 된다. 스크롤 중 선로드된 셀이 화면에 들어오는 건 가장 흔한 경로라 이중 디코딩이 잦았을 것. `ThumbnailScheduler.reprioritize(_:to:)`를 추가(대기 중이면 우선순위만 바꾸고 true, 실행 중이면 false)하고 Provider는 그 결과와 무관하게 기다린다. 테스트 2개 추가(Scheduler 1, Provider 1).
- 계획의 `Box` 클래스에 초기화자가 없어 컴파일 불가 → `init(_:)` 추가(sonnet 보고, 동작 동일).
