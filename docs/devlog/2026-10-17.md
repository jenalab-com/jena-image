# 2026-10-17 — 그리드 다중 선택: Cmd 토글 · Shift 범위(Finder 방식)

## 요청
Cmd 클릭은 클릭한 것만 더하고 빼기, Shift 클릭은 처음 선택한 것부터 클릭한 것까지 전부 선택.

## 배경
`allowsMultipleSelection`은 켜져 있었지만 `DoubleClickCollectionView.mouseDown`이 수정키를 보지 않았다.
- Shift 클릭이 Finder처럼 "앵커 ~ 여기"로 동작하지 않음.
- 이미 선택된 항목을 Cmd 클릭해 선택 해제하면 "선택된 항목 클릭"으로 잡혀 이름 변경 타이머가 돌았다.

## 변경 (`Sources/browser/BrowserViewController.swift`, `DoubleClickCollectionView`)
- `selectionAnchor`(마지막으로 수정키 없이 또는 Cmd로 클릭한 항목) + `anchorSelection`(그 직후 선택 집합).
- Shift 클릭: 기본 구현을 타지 않고 `anchorSelection ∪ [anchor...clicked]`를 선택. 앵커가 없으면 클릭 항목이 앵커. 목록 길이를 넘는 앵커(항목 삭제 뒤)는 무시.
- 일반 클릭·Cmd 클릭은 기본 구현(단일 선택·토글) 뒤 앵커 갱신.
- 이름 변경 트리거(`onClickSelectedItem`)는 수정키가 없을 때만.
- `display`/`displayBookmarks`에서 `resetSelectionAnchor()`.

## 검증
- `make build` 경고·에러 0, `make test` 26/26.
- 수동: ① A 클릭 → Shift로 F 클릭 → A~F 선택 ② Cmd로 B·D 클릭 → 둘만 토글 ③ Cmd로 B 클릭(앵커) → Shift로 F 클릭 → 기존 선택 + B~F ④ 선택된 항목 Cmd 클릭 → 해제되고 이름 변경 안 뜸 ⑤ Shift 클릭 뒤 드래그 안 시작됨(의도) ⑥ 폴더 셀 포함 범위도 정상 — 사용자 확인 대기.

# 2026-10-17 — 사고: 사이드바 등록 폴더 목록 소실 → 경로 저장으로 전환

## 증상
사용자: "추가된 폴더가 안 보여." `defaults`의 `folderBookmarks`가 빈 배열. plist 수정 14:05 = 번들 전체 ad-hoc 서명(`482adb1`)을 적용한 빌드의 첫 실행 시각.

## 원인 (두 겹)
1. `SecurityScopeService.restoreBookmarks()`가 복원 실패 항목을 **버리고 그 결과를 다시 저장**했다. 외장 디스크 미연결 상태로 켜도 그 폴더가 영구 삭제되는 결함.
2. security-scoped 북마크는 앱의 **코드 서명 identifier**에 묶인다(실험으로 확정, 아래). 어제 "손상됨" 수정의 `codesign --deep --sign -`이 번들 identifier를 `JenaImage`(링커 서명, 실행 파일 이름)에서 `com.jenalab.jenaimage`(CFBundleIdentifier)로 바꿨다. 이 Mac에서 새 identifier의 빌드를 처음 켠 14:05에 전부 복원 실패 → 1번 코드가 목록을 비웠다. 이 앱은 **샌드박스가 아니라** security scope가 애초에 불필요했다.
   → 책임: 서명 변경의 부작용을 검토하지 않은 검토자(하루) 몫.

### 실험 (macOS 26, 2026-10-17)
같은 폴더의 security-scoped 북마크를 ad-hoc 서명 CLI 둘로 교차 복원:
- identifier 같고 cdhash 다름(= 리빌드) → **성공**. 매 빌드마다 깨지는 건 아니다.
- identifier 다름 → **실패** `The file couldn't be opened because it isn't in the correct format`. 일반 옵션 복원은 성공.
- 1.6.1 릴리스 앱: `Identifier=JenaImage`(linker-signed) / 현재 빌드: `Identifier=com.jenalab.jenaimage`. → 1.6.1 → 재서명 1.7.0 업그레이드는 이 Mac 기준으로 목록을 지운다.
- 사용자 보고: 다른 Mac에선 재서명 1.7.0을 켜도 목록이 유지됐다. 이 실험 결과와 어긋나며 원인 미상(macOS 버전 차이 가능). 어느 쪽이든 경로 저장으로 바꾸면 서명과 무관해진다.

## 수정 (`Sources/services/SecurityScopeService.swift`)
- 저장을 **경로 문자열 배열**(`rootFolderPaths`)로 전환 — `folderColors`·`imageBookmarks`와 같은 방식. 서명·빌드와 무관.
- 복원 실패로 항목을 지우지 않는다. 존재하지 않는 경로도 그대로 돌려준다(사용자 제거만이 삭제).
- 옛 `folderBookmarks`는 첫 실행에 한 번 경로로 이관 시도(security scope → 일반 북마크 순). 옛 데이터는 남겨 둔다.
- 공개 API(`restoreBookmarks/addBookmark/removeBookmark/startAccessing`) 이름 유지, 호출부 변경 없음.

## 복구 시도 (실패)
Time Machine 대상 미마운트로 백업 복구 불가. `folderColors` 키에 남은 상위 경로 8개(`~/Documents/project/{armo, jenalab쇼츠, movie_source, music, 창업지원, 캐릭터, 특허, render_image}`, 전부 실존)를 `rootFolderPaths`에 NFD(파일시스템 형태, folderColors 키와 동일)로 기록. **사용자 확인: 이 8개는 원래 목록이 아니다**(색은 하위 폴더에 붙어 있었음). 추정 복구는 틀렸고, 사용자가 직접 다시 추가하기로 함. 원래 목록은 복원 불가.

## 영향 범위 — 릴리스
**v1.7.0 dmg(재서명본)는 옛 복원 코드를 담고 있어, 1.6.1 사용자가 설치해 처음 켜면 같은 방식으로 폴더 목록이 지워진다.** 다른 Mac에 설치한 1.7.0도 이미 켰다면 거기 목록도 비었을 것. → 이 수정으로 **v1.7.1 핫픽스** 필요. 1.6.1→1.7.1 이관도 서명이 바뀐 뒤라 옛 북마크 복원은 대개 실패하므로 한 번은 폴더를 다시 추가해야 한다(단, 더는 조용히 지워지지 않는다).
