# JenaImage 인터넷 P2P 이미지 공유 설계 (v2)

> 2026-11-13 작성. [p2p-sharing-design.md](p2p-sharing-design.md)(v1, 로컬 네트워크 전용)를 대체한다.
> v1의 읽기 전용 원칙·화면 구성·정보 모델·오류 상태는 그대로 잇고, **발견·접근·전송** 계층을 인터넷용으로 다시 정의했다.
> 기술 검증(2026-11-13): UPnP 포트 개방 → 외부 체커에서 TCP 도달 확인, 공개 DHT(Mainline) ping·get_peers·token 수신 확인, Bonjour 1:N 발견 확인.

## 1. 한 문장 정의

폴더 공유를 켠 Mac이 **개인 서버**가 되고, 다른 사용자는 중앙 서버 없이 **DHT로 열린 공유를 찾아** 그 Mac에 직접 붙어 이미지를 **보고 가져오기만** 한다. 1:N이며, 기본은 초대 코드를 아는 사람끼리만 보이는 **비공개 채널**이다.

## 2. 작가 결정 (2026-11-13)

| 결정 | 내용 |
|---|---|
| 연결 범위 | 인터넷 너머. 로컬 네트워크는 특별 취급하지 않는다(같은 망이면 자연히 더 빠를 뿐). |
| 중앙 서버 | 없음. 발견은 공개 DHT, 전송은 공유자 Mac 직접 연결. |
| 찾기 ≠ 가져오기 | 발견은 DHT(UDP), 전송은 읽기 전용 HTTP(TCP). 서로 다른 방식이어도 된다. |
| 채널 | **기본 비공개**(초대 코드). 공개 채널은 옵션. |
| 공개 채널 이름 | 공개로 켤 때 **표시 이름을 반드시 정한다**(Mac 이름 자동 노출 안 함). |
| IP 노출 | 화면 어디에도 상대·자기 공인 IP를 **표시하지 않는다**. 시스템 수준 노출은 한계로 명시. |
| 접근 제한 | 공유한 폴더 **밖은 어떤 경로로도 접근 불가**. 서버가 경로를 받지 않고 불투명 ID만 받는다. |
| 블록체인 | 쓰지 않는다. 필요한 건 장부가 아니라 분산 탐색(DHT)이다. |

## 3. 목표와 비목표

### 3.1 목표
- 공유 켜기 → 코드 전달 → 상대 화면에 목록이 뜨고 썸네일·원본을 받는다. 중간에 서비스 가입·서버 없음.
- 공유 폴더 하나당 서버 세션 하나. 보는 쪽은 여러 공유를 한 목록에서 본다.
- 공유자 Mac이 꺼지면 사라진다. 보관·중계 없음(그건 후속 "서버 링크 공유"의 몫).

### 3.2 비목표(1차)
- 원격 업로드·수정·삭제·이름 변경(프로토콜에 명령 자체가 없음).
- 오프라인 피어 대신 파일 보관, 검색 엔진식 전역 검색, 댓글·평점.
- NAT을 못 여는 환경의 강제 연결(중계 없음 → 명확한 안내로 끝).
- 하위 폴더 재귀 공유(2차).

## 4. 채널 모델

```text
채널 키 = SHA1("jenaimage/v1/" + 채널 비밀)
  비공개: 채널 비밀 = 초대 코드(앱이 생성, 예: "k7f2-9qzx-m3pd", 60비트 이상 엔트로피)
  공개:   채널 비밀 = "public"          → 모든 앱이 아는 고정 키 하나
```

- 공유자는 공유를 켤 때 채널 키에 **자기 (IP:포트)** 를 DHT에 announce한다(토렌트의 `announce_peer`와 동일).
- 보는 쪽은 채널 키로 `get_peers` → 피어 목록 → 각 피어의 `/manifest`를 받아 사이드바 목록을 만든다.
- 초대 코드는 공유자가 사이드바 행 우클릭 "초대 코드 복사"로 전달한다(메신저 등 앱 밖). 받는 쪽은 "채널 참가…"에 붙여 넣는다. 참가한 채널은 저장되어 재시작 후에도 목록에 남는다.
- 한 Mac은 채널 여러 개에 동시에 참가·공유할 수 있다. 공유 폴더 하나는 채널 하나에만 속한다(섞이지 않게).
- 공개 채널의 피어는 누구나 볼 수 있으므로, 공개 공유를 켤 때 **표시 이름 입력을 강제**하고 announce 전에 이름이 비면 켜지지 않는다.

## 5. 사용자 경험

### 5.1 공유하는 사람
1. 사이드바 폴더 우클릭 → **"인터넷으로 공유…"**.
2. 시트: 채널 선택(기존 비공개 채널 / 새 비공개 채널 만들기 / 공개), 공개면 표시 이름 필수. "공유 폴더 밖은 접근할 수 없습니다 · 읽기 전용" 안내 고정.
3. "공유 시작" → 상태가 순서대로 바뀐다: 포트 여는 중 → 네트워크에 알리는 중 → **공유 중 (N명 접속)**.
4. 포트를 못 열면 "외부에서 이 Mac에 접근할 수 없어요" 상태와 수동 포트포워딩 안내(IP는 보이지 않고 포트 번호만). 보는 쪽에는 이 공유가 아예 나타나지 않는다.
5. 중지하면 DHT에서 사라지고(최대 몇 분 캐시), 포트 매핑을 닫는다. 앱 종료 시 자동 중지.

### 5.2 받는 사람
1. 사이드바 **네트워크 공유** 섹션. 참가한 채널별로 묶인다.
2. "채널 참가…"에 초대 코드 입력 → 채널이 섹션에 생기고, 열린 공유가 행으로 뜬다.
3. 행 선택 → 원격 그리드(읽기 전용 배지, 공유 이름, 이미지 수). 썸네일은 보이는 것부터 받는다.
4. 선택 → 다운로드 → 저장 폴더 선택(기본값 기억) → 진행률. 받은 파일은 그 순간부터 보통 로컬 파일.

### 5.3 화면에서 절대 보여주지 않는 것
- 공인 IP·내부 IP·피어 ID 원문. 진단이 필요하면 설정 → 고급의 "연결 진단 복사"로만(클립보드, 화면 미표시).
- 공유자의 절대 경로·Mac 호스트명(공개 채널은 표시 이름만).

### 5.4 사이드바 예시

```text
네트워크 공유
  내 공유
    render_image          42   · 공유 중 · 2명
  비공개 · 스튜디오 팀
    민수 작업본            128  · 온라인
    촬영 원본              —    · 오프라인
  공개
    JenaLab 샘플           60   · 온라인
  [채널 참가…]
```

## 6. 정보 모델

v1의 `RemoteShare`·`RemoteImage`를 유지하고 채널을 더한다.

```swift
Channel
- id: UUID
- kind: .private(inviteCode: String) | .public
- displayName: String            // 비공개는 사용자가 붙인 별칭, 공개는 "공개"
- key: Data                      // SHA1 채널 키(파생값, 저장은 비밀만)

HostedShare                      // 이 Mac이 켠 공유
- id: UUID
- folderURL: URL                 // 로컬에만 존재, 절대 네트워크로 나가지 않음
- channelID: UUID
- publicName: String?            // 공개 채널일 때 필수
- state: .openingPort | .announcing | .live(peers: Int) | .unreachable | .stopped
- fileIndex: [UUID: URL]         // 불투명 ID → 폴더 안 파일 (서버는 이 표만 본다)

RemoteShare / RemoteImage        // v1과 동일. 절대 경로·IP 미보유
- endpoint는 모델 밖(연결 계층)에만 둔다
```

## 7. 아키텍처

```text
services/sharing/
  DHTClient            Mainline DHT(KRPC/bencode, UDP). ping·find_node·get_peers·announce_peer, 라우팅 테이블, 15분 재announce
  PortMapper           UPnP IGD(SSDP+SOAP) → NAT-PMP → IPv6 직접 순으로 시도. 임대 갱신, 종료 시 해제
  ShareServer          읽기 전용 HTTP/1.1 서버(Network.framework). 경로가 아니라 ID만 받음
  ShareClient          manifest·썸네일·원본 수신, 동시성 제한, 재시도
  ChannelStore         채널·초대 코드·참가 목록(UserDefaults 아님 — Keychain에 비밀, 메타는 파일)
  SharingCoordinator   위 다섯을 묶고 상태 머신을 가짐. MainWindowController는 이것만 안다
```

의존 방향: UI → `SharingCoordinator` → 각 서비스 → Model. 기존 `ImageFile`·`ThumbnailProvider`는 원격 경로를 모른다. 외부 의존성 없음 원칙 유지(DHT·UPnP·HTTP 전부 직접 구현).

## 8. 프로토콜

### 8.1 발견 (DHT)
- Mainline DHT(BEP 5)를 그대로 쓴다. 부트스트랩: `dht.transmissionbt.com:6881` 등 공개 노드 3~5개 + 마지막에 만난 노드 100개를 로컬에 저장해 다음 시작에 먼저 시도.
- 공유 켜기 = 채널 키에 `announce_peer(port)`. 15분마다 갱신, 중지 시 갱신 중단(DHT는 보통 30분 안에 잊는다).
- 보기 = 채널 키로 `get_peers` → `values`의 (IP:포트) 목록. 응답한 피어마다 `/manifest`를 받아 실제 JenaImage인지 확인한 것만 목록에 올린다(채널 키를 모르는 제3자가 쓰레기 announce를 해도 manifest 검증에서 걸러진다).
- DHT 노드 ID는 앱 설치마다 무작위 고정. 포트는 UDP 하나(6881 아님, 임의 고정) — TCP 서버 포트와 같아도 된다.

### 8.2 접근 (포트)
- UPnP IGD `AddPortMapping`(TCP+UDP, 임대 1시간, 갱신) → 실패 시 NAT-PMP → 실패 시 IPv6 전역 주소가 있으면 그대로 → 전부 실패면 `.unreachable`.
- 외부 도달 확인: announce 후 DHT에서 자기 자신을 `get_peers`로 되찾아 보고, 다른 피어가 `/manifest`를 받아 간 로그가 있으면 `live`. 자체 외부 체커 서비스는 두지 않는다(서버 없음 원칙).

### 8.3 전송 (HTTP, 읽기 전용)

```text
GET /manifest                 → { proto: 1, shareID, name, imageCount, images: [{id, name, bytes, revision}], pubkey }
GET /thumb/{id}?max=440       → image/heic 또는 image/jpeg (ThumbnailProvider 캐시 재사용)
GET /file/{id}                → 원본 스트리밍, Range 지원(이어받기)
그 외 모든 메서드·경로         → 404. PUT/POST/DELETE는 라우팅 자체가 없음
```

- **경로를 받지 않는다.** `id`는 공유를 켤 때 만든 UUID이고 `HostedShare.fileIndex`에만 매핑된다. 디렉터리 순회·`..`·심볼릭 링크 문제가 설계상 생기지 않는다.
- `fileIndex`는 공유 폴더의 직속 이미지만 담는다. 폴더 밖을 가리키는 심볼릭 링크·패키지·숨김 파일은 색인에서 제외(FolderWatcher로 변경 시 재색인, 삭제된 파일 ID는 즉시 404).
- 인증: 비공개 채널은 `Authorization: Bearer HMAC(채널 비밀, 날짜)`를 요구해 채널 비밀을 모르면 manifest조차 못 받는다. 공개 채널은 토큰 없음.
- 암호화: 1차는 TLS 없이 간다(자기 서명 TLS + DHT 공개키 검증은 2차). 1차 문서·UI에 "전송은 암호화되지 않음"을 명시한다. 비공개 채널의 토큰이 노출돼도 읽기 전용이라 피해 범위는 "그 폴더 열람"으로 한정.
- 동시 연결 상한(기본 8), 피어당 대역폭 상한 옵션, 과도한 요청 피어 일시 차단.

## 9. 보안·개인정보

- **폴더 밖 접근 불가**는 UI 숨김이 아니라 서버 구조로 보장한다(8.3). 테스트 13.1의 필수 항목.
- 화면에 IP 미표시(5.3). 단, 네트워크 관찰자·DHT 피어는 IP를 알 수 있다 — 도움말에 한 줄로 명시한다.
- 공개 채널: 표시 이름 필수, 이름 중복 허용(피어 ID로 구분, 화면엔 이름+이미지 수만). 신고·차단은 보는 쪽 로컬 차단 목록으로.
- 초대 코드는 Keychain. 앱 삭제 시 함께 사라진다. 코드 재발급 = 기존 채널 종료.
- 공유 폴더에 든 파일의 EXIF(GPS 등)는 그대로 나간다. 1차는 안내만, 2차에 "위치 정보 제거 옵션".

## 10. 오류와 빈 상태

| 상황 | 공유자 화면 | 보는 쪽 화면 |
|---|---|---|
| 포트 못 엶 | "외부에서 접근할 수 없어요 · 포트 N을 수동으로 열거나 다른 네트워크에서 시도" | 목록에 안 보임 |
| DHT 부트스트랩 실패 | "네트워크에 알리지 못했어요 · 잠시 후 재시도" | "열린 공유를 찾을 수 없어요" |
| 피어 오프라인 | — | 행에 "오프라인", 마지막 본 시각 |
| manifest 검증 실패 | — | 목록에서 제외(조용히) |
| 토큰 거부 | — | "초대 코드가 바뀌었어요 · 다시 참가" |
| 전송 중 끊김 | 접속자 수 감소 | 파일별 재시도·이어받기, 실패 목록 |

## 11. 단계별 구현

### Phase 0 — 기술 스파이크 (Swift, 앱 밖)
- `DHTClient`: 부트스트랩 → `get_peers` → `announce_peer` → 다른 Mac에서 되찾기. 두 컴퓨터(제롬님 환경)로 실측.
- `PortMapper`: UPnP IGD 추가·삭제·임대 갱신. 이 집 공유기(ipTIME 계열)에서 성공 확인됨, NAT-PMP는 미지원.
- 완료 기준: 집 ↔ 회사(또는 테더링) 사이에서 manifest 1회 왕복.

### Phase 1 — 비공개 채널 MVP
1. `ShareServer`(manifest·thumb·file, ID 기반, Range) + `HostedShare` 색인
2. `PortMapper` + `DHTClient` + `SharingCoordinator` 상태 머신
3. 공유 시트(비공개 채널만) · 사이드바 네트워크 섹션 · "채널 참가…"
4. 원격 그리드·썸네일·다운로드(v1 5장 그대로)
5. 원격 모드에서 쓰기 메뉴·단축키 차단, IP 미표시 점검
6. 테스트 + 두 Mac 수동 검증

### Phase 2 — 공개 채널·신뢰
- 공개 채널 + 표시 이름 강제 + 로컬 차단 목록
- TLS(자기 서명) + DHT 공개키 검증, 전송 취소·재시도 다듬기
- 하위 폴더 재귀 공유, 위치 정보 제거 옵션

### Phase 3 — 도달 불가 사용자를 위한 유료 중계 (서버 링크 공유와 합류)
- `.unreachable`인 공유자에게 "중계로 공유하기(구독)" 제안. 여기서부터 서버가 생긴다.

## 12. 테스트 계획

### 12.1 단위
- bencode 인코딩/디코딩 왕복, KRPC 메시지 생성·파싱, 라우팅 테이블 버킷 분할.
- `ShareServer`: `/file/{모르는 id}` 404, `../`·절대 경로·심볼릭 링크 포함 URL 전부 404, PUT/POST/DELETE 404, Range 응답, 토큰 없는 비공개 요청 401.
- `fileIndex`: 폴더 밖 심볼릭 링크·숨김·패키지 제외, 삭제 파일 ID 즉시 무효.
- `PortMapper`: SOAP 요청 본문, 실패 시 다음 방식으로 폴백.

### 12.2 UI
- 공유 시트: 공개 선택 시 이름 비면 "공유 시작" 비활성.
- 네트워크 섹션에 IP·경로 문자열이 절대 렌더링되지 않음(접근성 트리 검사).
- 원격 모드에서 삭제·이름 변경·이동·붙여넣기 메뉴 비활성.

### 12.3 실망 검증 (두 Mac, 서로 다른 네트워크)
- 집 Mac 공유 → 테더링 Mac에서 코드 참가 → 목록·썸네일·원본 다운로드.
- 공유 중지 → 상대 목록에서 사라지는 시간 측정.
- UPnP 끈 공유기 → `.unreachable` 안내 확인.
