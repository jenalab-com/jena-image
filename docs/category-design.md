# 이미지 카테고리

## 목적과 범위

서로 다른 폴더에 있는 이미지를 원본 이동 없이 목적별로 모아 본다. 사용자가 요청한
이름만 입력하는 카테고리 추가, 목록 우클릭·상세 화면 지정, 사이드바 카테고리 목록,
카테고리별 이미지 조회, 상단 폴더/카테고리 보기 전환을 제공한다.

- 사용자 확인: 한 이미지를 여러 카테고리에 지정할 수 있다.
- 가정: 기존 로컬 단일 사용자 앱의 저장·UI 방식을 따른다. 영상은 기존 이미지 북마크처럼 제외한다.
- 계층형 카테고리, 카테고리 삭제, 검색, 외부 이동 자동 추적은 이번 요청 범위에서 제외한다.
- 수집 순서대로 표시하며, 분류를 해제해도 원본 파일과 다른 카테고리의 지정은 유지한다.

## 사용 흐름

1. 사이드바 상단 태그 아이콘으로 카테고리 보기를 켠다. 폴더 아이콘으로 폴더 탐색에 돌아간다.
2. 카테고리 보기의 + 버튼 → 이름 입력 → 추가. 빈 이름과 중복 이름은 입력을 유지하며 안내한다.
3. 폴더·북마크·카테고리 이미지 목록의 우클릭 → **카테고리 지정** → 카테고리 체크/해제.
4. 여러 장 선택 시 모두 지정되었으면 해제하고, 일부 또는 전부 미지정이면 모두 추가한다.
   일부만 지정된 상태는 메뉴의 혼합 체크 상태로 표시한다.
5. 이미지 상세 하단 **카테고리** 버튼에서도 같은 메뉴를 연다.
6. 지정 메뉴의 **새 카테고리…**는 이름을 입력하면 현재 이미지들을 함께 지정한다.
7. 사이드바의 카테고리 행을 누르면 해당 이미지 목록을 표시한다. 상세에서 분류를 바꿔도
   상세는 유지하며 뒤로 돌아갈 때 갱신된 카테고리 목록을 보여준다.

8. 카테고리 행 더블클릭 또는 우클릭 → **이름 변경** → 현재 이름이 채워진 창에서 수정.
   취소하면 유지하며, 빈 이름과 다른 카테고리와 중복되는 이름은 저장하지 않는다.
   카테고리 ID·이미지 지정·목록 순서는 그대로 보존한다.

## 설계 결정

기존 `BookmarkStore`와 별도인 `CategoryStore`가 `UserDefaults`의 `imageCategories.v1`에
UUID·이름·정규화된 파일 경로 배열을 JSON으로 저장한다. 북마크·등록 폴더 키는 수정하지 않는다.
DB 도입과 북마크 저장소 확장도 고려했으나, 현재 데이터와 기능을 분리하는 작은 저장소를 선택했다.
메타데이터 규모가 매우 커지면 전체 배열 읽기/저장 비용을 다시 평가해야 한다.

- 영속 상태: 카테고리 ID/이름/멤버 경로. `CategoryStore`가 유일한 변경 지점이다.
- 화면 상태: 사이드바 보기 모드, 현재·마지막 카테고리 ID, 브라우저/뷰어 모드.
- 비동기 작업 상태: 폴더 열거 세대 번호. 이후 선택한 분류 화면을 이전 결과가 덮지 못한다.
- `MainWindowController+Categories`가 저장소와 sidebar/browser/viewer를 연결한다.
- 기존 `NSOutlineView` source-list, SF Symbols, 시스템 색·서체·버튼을 재사용한다.
  대상은 폴더 기반으로 이미지를 관리하는 기존 사용자이며 시각적 장식이나 새 테마는 도입하지 않는다.

## 오류·데이터 보존

- 카테고리 없음과 카테고리 내 이미지 없음에 각각 안내를 표시한다.
- 외장 디스크 미연결·외부 삭제 등으로 원본이 없어도 분류 경로를 자동 삭제하지 않는다.
  기존 그리드의 누락 파일 표시를 사용하며 카테고리에서 빼기는 가능하다.
- JSON 읽기 실패 시 오류를 표시하고 기존 바이트를 덮어쓰지 않는다.
- 앱 내부 파일/폴더 이동·이름변경 성공 시 하위 경로까지 갱신한다.
- 앱에서 사용자가 원본을 휴지통으로 보내는 데 성공하면 해당 경로를 분류에서도 제거한다.
- 가상 분류에는 파일 붙여넣기 대상 폴더가 없으므로 붙여넣기를 비활성화한다.
- Finder 등 앱 밖에서 이동한 파일은 자동 추적하지 않는다. 기존 경로를 유지한다.

## 검증 기준

요청한 6개 흐름을 구현하고, 기존 테스트를 유지하며 다음 회귀를 자동 확인한다:
다중 분류 독립성, 재시작 복원, 중복 방지, 누락·손상 데이터 보존, 북마크·폴더 키 불변,
사이드바 전환·선택, 목록과 상세의 지정 메뉴, 상세 유지와 복귀, 늦은 폴더 열거 무시,
이름변경·이동 후 목록 유지. UI 테스트는 독립 UserDefaults와 메모리 캐시를 사용한다.
