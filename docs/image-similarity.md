# 비슷한 이미지 찾기

## 사용 방법

1. 검색할 이미지가 있는 폴더·북마크·카테고리 목록을 연다.
2. 폴더·북마크·카테고리 목록에서 기준 이미지 한 장을 우클릭하고 **비슷한 이미지 찾기**를 선택한다.
3. **현재 목록의 이미지 안에서만** 가까운 순서로 최대 100장을 표시한다. 기준 이미지 자체는 제외한다.
   스크롤 밖의 항목도 포함하지만 다른 폴더를 추가로 탐색하지 않는다. 폴더 등록은 필수가 아니다.
4. 결과를 여러 장 선택하고 **카테고리 지정**으로 수집한다. 새 카테고리도 만들 수 있다.
5. 결과를 더블 클릭하면 상세 화면으로 열리고, 상세 화면을 닫으면 검색 결과로 돌아온다.
   검색 결과 상단의 뒤로 버튼은 검색을 시작했던 폴더·북마크·카테고리로 돌아간다.

검색 결과에서는 파일명 정렬 대신 유사도순을 유지한다. 가장 가까운 후보를 보여주는 검색이므로,
모든 결과가 실제로 비슷하다고 보장하지는 않는다. 결과에서 다시 검색하면 현재 결과 목록 안에서 찾는다.
새로 추가되거나 변경된 이미지까지 포함하려면 출발 목록을 갱신한 뒤 **비슷한 이미지 찾기**를 다시 실행한다.

## 모델과 실행 환경

- **모델/API:** Apple Vision의 내장 이미지 특징 추출 기능,
  `VNGenerateImageFeaturePrintRequest`, **revision 2**.
- 최소 환경: **macOS 14 이상**. 앱이 사용하는 Swift/AppKit 프로세스 안에서 Vision 프레임워크를 호출한다.
- 별도의 `.mlmodel` 다운로드, Python, Ollama, 서버 실행, API 키가 필요 없다.
- Apple이 제공하는 내장 특징 추출기를 사용한다. CLIP이나 생성형 LLM을 탑재한 구현은 아니다.
  외부에 공개된 특정 가중치 파일이나 임의의 모델 크기를 모델명으로 안내하지 않는다.
- 이미지 전송이나 외부 추론 API 호출이 없다. 분석 결과도 Mac의 로컬 캐시에 저장한다.

프로젝트 루트에서 빌드한다. 기존 빌드를 보존하려면 별도 경로를 지정할 수 있다.

```sh
make build BUILD_DIR=/tmp/jena-image-ai-build
open /tmp/jena-image-ai-build/JenaImage.app
```

추론은 첫 검색부터 앱 안에서 실행된다. 별도 학습은 하지 않는다.
새 이미지의 최초 분석은 개수·형식·디스크와 Mac 성능에 따라 시간이 걸린다.
진행 창의 **취소**로 중단할 수 있다. 실행 중인 한 장의 Vision 요청은 끝난 뒤 취소를 확인한다.

## 처리 방식

1. 검색 시작 시점에 현재 브라우저 목록의 이미지 URL을 복사한다. 영상·기준 이미지·중복 경로는 제외한다.
   디렉터리를 열거하거나 현재 목록 밖의 이미지를 추가하지 않는다. 하위 폴더 포함 보기라면 이미 목록에 포함된 하위 폴더 이미지도 검색한다.
2. ImageIO로 원본에서 최대 512px 이미지를 만든다. EXIF 회전을 반영한다.
   화면 체크무늬나 HEIC 썸네일 캐시를 모델 입력으로 쓰지 않는다.
3. 투명 이미지의 알파는 분석용 중간 회색 바탕에 합성한다. 원본 파일은 바꾸지 않는다.
4. Vision revision 2와 `scaleFit`으로 특징을 추출한다.
5. `VNFeaturePrintObservation.computeDistance`로 기준 이미지와의 거리를 비교한다.
   거리가 작을수록 가까우며, 이를 확률이나 정확도 퍼센트로 표시하지 않는다.

분석과 캐시 I/O는 전용 actor에서 수행하고 이미지 한 장씩 처리한다.
목록은 기존 masonry·격자, 선택, 북마크, 카테고리 지정 기능을 재사용한다.

## 저장과 갱신

캐시 위치:

```text
~/Library/Caches/com.jenalab.jenaimage/similarity-v1/
```

캐시는 이미지별 JSON 파일이다. 검색 결과의 순위나 원본 이미지 사본을 저장하는 것이 아니라,
모델이 추출한 특징 데이터를 보안 아카이브한 뒤 JSON의 Data 필드로 저장한다.
다른 기준 이미지로 검색해도 같은 특징을 읽어 거리만 새로 비교하므로 재사용할 수 있다.

경로의 SHA-256을 파일명으로 사용하며, 수정 시각·크기·Vision 리비전·입력 처리 버전·OS 버전과
보안 아카이브한 특징을 저장한다. 같은 조건이면 재실행 후에도 재사용한다.
캐시가 없어지면 다음 검색 때 다시 분석한다. 이번 목록 범위 변경에서도 기존 캐시 경로·형식·모델 버전을 유지한다.
파일이나 버전이 바뀌거나 캐시가 손상되면 해당 이미지만 다시 분석한다.
저장 공간 문제로 캐시를 쓰지 못해도 현재 검색은 계속하며 완료 시 알린다.
검색할 때마다 현재 목록의 이미지들에 대해 캐시를 확인한다. 목록에 남아 있지만 원본이 사라진 이미지는 건너뛴다.
이동·이름 변경된 파일은 새 경로에서 다시 분석한다. 사용자가 등록한 폴더·카테고리는 수정하지 않는다.

## 범위와 한계

- 시각적 특징 기반 검색이다. ‘쓸쓸한 분위기’처럼 추상적인 감정이나 작가의 의도를 정확하게 이해하는 기능은 아니다.
- ImageIO로 분석 이미지를 만들 수 없는 형식과 손상 파일은 건너뛴다. SVG·AI 등 미리보기 전용 형식은 결과에 없을 수 있다.
- 미다운로드 iCloud 파일은 자동으로 다운로드하지 않는다. Finder에서 먼저 다운로드한 후 다시 검색한다.
- 현재 목록에서 읽거나 분석할 수 없는 이미지 수는 완료 안내에 표시한다. 영상은 검색 범위에서 제외한다.
- 결과는 실행 시점의 목록이다. 자동 폴더 갱신으로 유사도순을 다른 폴더 목록으로 대체하지 않는다.
- 검색 결과와 특징 캐시는 자동 카테고리 분류가 아니다. 최종 카테고리 수집은 사용자가 선택한다.
