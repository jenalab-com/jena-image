# 앱 안에서 업데이트 설치

> 2026-11-17 작성. 자동 업데이트가 아니라, 사용자가 메뉴에서 확인하고 설치를 누르면 앱이 스스로 교체·재실행한다.

## 결정

| 항목 | 내용 |
|---|---|
| 시작 | **JenaImage → 업데이트 확인…** 메뉴만. 실행 시 자동 확인 없음 |
| 배포 원천 | GitHub Releases 최신 릴리스(`releases/latest`)의 `.dmg` 첨부. 릴리스 절차는 그대로 |
| 무결성 | GitHub API가 주는 첨부 `digest`(`sha256:…`)와 크기를 내려받은 파일과 대조. 없으면 설치 거부 |
| 대상 확인 | DMG 안 앱의 번들 ID가 실행 중인 앱과 같고, 버전이 릴리스 버전과 같아야 한다 |
| 교체 | 도우미 셸 스크립트가 현재 앱 종료를 기다린 뒤 기존 앱을 옆으로 치우고 새 앱을 옮긴다. 실패하면 기존 앱을 되돌린다. 성공 후 새 앱을 연다 |
| 설치 불가 | 앱 번역(App Translocation)·읽기 전용 볼륨(DMG에서 실행)·상위 폴더 쓰기 불가면 **다운로드 페이지 열기**로 대신한다 |
| 의존성 | 없음. URLSession·CryptoKit·`hdiutil`·`ditto`·`xattr`만 사용 |
| 시험용 주소 | `defaults write com.jenalab.jenaimage updateFeedURL <url>`로 확인 주소를 바꾼다(검증·시연용, UI 없음) |

## 흐름

```text
업데이트 확인… → 확인 중 → 최신 버전입니다
                         → 새 버전 X.Y.Z (변경 내용) [나중에] [설치] / [다운로드 페이지 열기]
설치 → 내려받는 중(진행률) → 확인하는 중(해시·번들) → 앱을 다시 시작합니다 → 종료 → 교체 → 재실행
오류 → 이유 + [다운로드 페이지 열기] [닫기]
```

## 구성

- `services/AppUpdateService` — 최신 릴리스 조회·파싱, 버전 비교, 내려받기(진행률), SHA-256·크기 검증.
- `services/AppUpdateInstaller` — 설치 가능 여부 판단, DMG 마운트 → 번들 확인 → 같은 볼륨의 임시 폴더로 복사 → 격리 속성 제거 → 분리, 교체 스크립트 실행.
- `app/UpdateWindowController` — 상태 표시 창. 서비스와 설치기는 주입 가능(테스트).

## 릴리스할 때 지킬 것

- 태그(`v2.1.0`)와 DMG 안 앱의 `CFBundleShortVersionString`(Info.plist)이 같아야 한다. 다르면 설치를 거부한다.
- DMG 첨부는 릴리스에 하나만 둔다(이름 끝이 `.dmg`인 첫 첨부를 쓴다). 해시는 GitHub가 자동으로 만든다.
- 설치는 앱을 종료하므로 "설치"는 Enter 기본 버튼이 아니다(실수로 누른 Enter 방지). "확인"·"다시 시도"만 Enter에 반응한다.

## 한계

- ad-hoc 서명이라 업데이트 후 macOS가 폴더 접근 등 개인정보 권한을 다시 물을 수 있다. 근본 해결은 Developer ID 서명.
- GitHub 비인증 API는 IP당 시간당 60회. 수동 확인에는 충분하며, 초과 시 안내한다.
- 교체는 같은 이름·같은 위치로만 한다. 사용자가 앱 이름을 바꿨어도 그 경로에 설치한다.
