# 대량 이미지 탐색과 미리보기 작업 제한

## 배경과 가정

대량 이미지 목록과 외장 저장장치에서 UI 스레드의 파일 조회, 표시 전에 수행하는 캐시 저장, 취소되지 않는 디코딩·폴더 집계가 응답성을 떨어뜨릴 수 있다. 기존 AppKit/서비스 구조, 실제 썸네일 비율 우선 정책, iCloud 미다운로드 파일을 썸네일 목적으로 내려받지 않는 정책을 유지한다.

## 결정

- 목록의 캐시 비율 복원과 스탬프 검증은 백그라운드에서 수행한다. 보이는 셀의 기존 동기 캐시 적중 API와 외부 수정 검증은 유지한다.
- 그리드는 원본 비율을 읽지 않는다. masonry는 유효한 캐시 비율을 먼저 재사용하고, 재배치 갱신은 150ms 단위로 합친다.
- 썸네일 결과 전달을 디스크 인코딩보다 먼저 예약한다. 저장은 utility 직렬 큐에서 수행하며 16개 슬롯을 둔다. 한도에 도달하면 생성 워커만 기다려 메모리를 제한한다. 저장 요청은 버리지 않는다. 원본 스탬프와 비우기 세대로 오래된 대기 저장을 걸러낸다.
- 원본 이미지 로딩은 공용 actor에서 한 장씩 수행한다. 호출자 취소를 detached Task에 전달하고, 시작 전·완료 후 확인한다.
- 색상 보정 미리보기는 별도 actor에서 긴 변 1600px의 소스를 재사용한다. 40ms 입력 병합과 취소 검사로 최신 조절 값을 우선한다. 적용·저장은 기존 원본 해상도로 유지한다.
- 폴더 개수 집계는 직렬 OperationQueue로 제한하고 상위 폴더 작업에 하위 요청을 합친다. 무효화 시 작업을 취소하고 재귀 방문마다 확인한다.
- 재귀 탐색은 로딩 상태와 빈 결과를 구분한다. 32장 발견 또는 200ms 경과 시 진행 상황을 알리고 최대 64장의 첫 묶음을 보여준다. 완료 시 기존 정렬을 적용한다. 세대 검사로 늦은 결과를 차단하고 미리보기 선택을 보존한다.

## 검토한 대안과 절충

- 파일 변경 검증을 제거하는 대신 백그라운드로 이동해 외부 편집 반영을 유지했다.
- 저장 큐 초과분을 버리지 않고 워커에 역압을 적용했다. 저장장치가 계속 느리면 후속 썸네일 생성 속도도 제한되지만 메모리와 저장 정책을 지킨다.
- 전체 열거 완료를 기다리는 대신 제한된 첫 묶음을 표시했다. 탐색 중 순서는 발견 순이며, 완료 시 사용자 정렬 순서로 재배치된다.
- 전체 원본을 계속 병렬 디코딩하는 대신 한 장씩 처리한다. 비교 화면 초기 로딩은 순차 처리되며, 메모리 사용량을 우선 제한한다.
- 이미 실행 중인 ImageIO 호출·파일시스템 호출 자체를 강제로 중단하지는 못한다. 다음 작업 또는 항목에서 취소를 반영한다.

## 검증과 한계

서비스 테스트 66개와 UI 테스트 50개가 통과했다. 저장 지연, 취소된 디코딩, 축소 미리보기, 중복 집계, 부분 탐색 표시, 폴더 전환과 뷰어 복귀를 자동 검증했다. 실제 대규모 사용자 라이브러리·외장 디스크에서의 시간 및 최대 메모리 수치는 아직 측정하지 않았다.
