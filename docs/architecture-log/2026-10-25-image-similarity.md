# 이미지 유사 검색에 Apple Vision 내장 특징 추출기 사용

## 배경과 가정

Swift/AppKit macOS 14+ 앱에서 기준 이미지와 비슷한 후보를 수집한다.
사용자는 간단한 기능을 원하며, 현재 등록 폴더·목록·카테고리 흐름을 재사용한다.
텍스트 검색, 서버, 대화형 AI, 자동 카테고리 분류는 이번 범위가 아니다.

## 검토한 선택지

- Apple Vision Image Feature Print: OS 내장, 앱에서 직접 호출, 별도 배포 모델 없음.
- CLIP 계열 모델의 Core ML 변환·탑재: 추후 텍스트 검색 확장에 유리하지만 모델 선택·변환·배포·추론 검증이 추가된다.
- 외부 임베딩 API: 이미지 업로드, 계정·키·비용과 네트워크 의존성이 생긴다.

## 결정과 이유

Vision `VNGenerateImageFeaturePrintRequestRevision2`를 고정 사용한다.
ImageIO로 EXIF를 반영한 최대 512px 입력을 만들고 투명 영역은 중간 회색에 합성한다.
전용 actor가 폴더 열거·특징 캐시·순위 계산을 담당하고, 창 컨트롤러가 진행/취소 및 목록 전환을 중재한다.
검색 결과에는 별도 브라우저 모드를 두어 북마크·카테고리 멤버십 제거와 파일명 정렬을 오작동시키지 않는다.
파일 수정 시각·크기·OS 및 모델 버전으로 캐시를 검증한다. 결과는 최대 100개만 유지한다.

## 수용한 한계

추상적인 ‘분위기’보다 시각적 유사도에 초점을 맞춘다. 임계값을 임의로 정하지 않고 가까운 후보를 제시한다.
첫 검색은 모든 로컬 이미지의 분석 시간이 필요하고 이후에도 디렉터리 열거와 특징 비교는 수행한다.
현재 결과는 스냅샷이며, 추가·수정된 파일의 순위 반영은 새 검색에서 수행한다.
상세 검색 사용법과 제외 형식·iCloud 처리는 [사용 문서](../image-similarity.md)에 기록한다.

## 검증

실제 Vision 추론으로 동일 이미지 최상위, 안전한 특징 아카이브 왕복, 서비스 재생성 후 캐시 재사용,
변경 파일 재분석, 손상 캐시 재생성, 취소, 읽지 못한 루트 보고를 검증한다.
UI는 검색 메뉴, 결과 카테고리 지정, 상세 복귀, 자동 갱신 시 결과 유지, 출발 목록 복귀와 늦은 결과 무시를 검증한다.
테스트는 임시 파일·설정·캐시만 사용한다.

## 후속 변경: 검색 범위를 현재 목록으로 제한

전체 등록 폴더 분석이 느리다는 사용자 요청에 따라 폴더 열거를 제거했다.
브라우저가 현재 목록의 전체 이미지 URL을 스냅샷으로 전달하며 서비스는 이 목록 안에서만 비교한다.
이는 스크롤 뷰포트에 한정되지 않는다. 캐시 형식과 모델 버전은 유지해 기존 특징을 그대로 재사용한다.
