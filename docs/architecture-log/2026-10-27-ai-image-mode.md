# AI CLI 실행과 파일 경계

## 문맥과 가정
단일 사용자 AppKit 앱이며 기존 구조는 UI → Service → Model이다. 브라우저 선택과 폴더 상태는 MainWindowController가 소유한다. 하나의 AI 창에서 한 번에 한 작업만 실행한다.

## 결정
`Sources/ai`에 요청 값 타입, 실행 서비스, 작업 창을 둔다. MainWindowController 확장이 선택 URL을 전달하고 저장 후 목록을 갱신한다. UI에 FileManager/ImageIO 처리를 넣지 않는다.

서비스는 백그라운드에서 Foundation Process를 직접 실행한다. 셸 문자열 평가 없이 인자를 전달한다. Codex는 `exec --sandbox workspace-write`와 이미지 인자를 사용한다. 사용자 지정 CLI는 JSON 요청 파일 경로를 유일한 인자로 받는다.

각 실행은 별도 임시 작업 폴더를 사용한다. 참조는 PNG 복사본으로 전달하고 출력 폴더의 실제 PNG만 검증·저장한다. 원본 경로와 최종 저장 폴더는 CLI 요청에 넣지 않는다. 이는 파일 전달 경계이며 사용자 지정 실행 파일 자체를 OS 샌드박스로 제한하지는 않는다.

프로세스와 취소 상태는 잠금으로 보호한다. 로그는 파일로 받아 파이프 교착을 피한다. 작업 폴더는 자동 삭제하지 않아 실패·부분 저장 시 복구할 수 있다. 사용자가 취소를 누를 때만 프로세스 종료를 요청하며 생성 중 창 닫기는 막는다.

## 대안과 절충
API 직접 호출은 요청된 CLI 흐름과 달라 제외했다. CLI마다 임의 인자 템플릿을 설정하는 대신 버전 1 JSON 계약을 선택해 셸 quoting과 참조 배열 전달을 명확하게 했다. 사용자 지정 CLI는 래퍼가 필요하다. Codex 생성 도구 지원은 환경 의존이며 실제 계정 생성 검증 전까지 provisional이다.

상태: 폼·결과·작업은 창 상태, 브라우저 선택은 기존 앱 상태, CLI 인증은 외부 CLI 소유. 추가 API 키 저장소는 만들지 않는다.
