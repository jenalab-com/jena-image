# JenaImage P2P 이미지 공유 설계

> 상태: 제안(구현 전) · 작성일: 2026-10-26 · 대상: macOS 14+
>
> 이 문서는 “특정 폴더를 지정하면 다른 사용자가 그 안의 이미지를 다운로드하고, 사이드바에서 공유 폴더 목록을 탐색하는 서버리스 P2P 커뮤니티”를 정의한다.

## 1. 한 문장 정의

사용자가 명시적으로 선택한 폴더만 같은 네트워크의 다른 Mac과 **읽기 전용으로 직접 공유**하고, 받는 사람은 사이드바에서 공유 폴더를 찾아 이미지를 썸네일로 확인한 뒤 원하는 파일만 다운로드한다.

## 2. 전제와 범위 결정

### 2.1 1차 MVP의 연결 범위

1차 MVP는 **같은 로컬 네트워크(Wi-Fi/유선 LAN)**로 제한한다.

- Bonjour로 주변 JenaImage 인스턴스를 자동 발견한다.
- 이미지 목록·썸네일·원본은 두 Mac 사이의 직접 연결로 전송한다.
- 중계서버, 계정 서버, 중앙 DB는 사용하지 않는다.

인터넷에 떨어진 사용자 간 연결은 후속 단계로 분리한다. 중계서버가 전혀 없다면 NAT/방화벽 환경에 따라 직접 연결이 실패할 수 있으며, 이를 완화하려면 초대 정보 교환, 외부 STUN, 수동 포트포워딩 같은 별도 방식이 필요하다. 따라서 “어디서나 반드시 연결된다”는 보장은 MVP 범위에 넣지 않는다.

### 2.2 공유 단위

- 공유 단위는 사용자가 고른 **루트 폴더 하나**다.
- MVP는 그 폴더의 **직속 이미지 파일**만 공유한다.
- 하위 폴더 재귀 공유는 후속 항목이다.
- 기존 사이드바에 등록된 모든 폴더를 자동 공개하지 않는다.
- 공유는 기본적으로 꺼져 있으며, 사용자가 폴더마다 명시적으로 시작·중지한다.

### 2.3 읽기 전용 원칙

받는 사용자는 다음만 할 수 있다.

- 공유 폴더 목록 조회
- 이미지 목록 조회
- 썸네일 조회
- 선택한 원본 다운로드

다음 동작은 UI에서 숨기는 데 그치지 않고 **네트워크 명령 자체로 정의하지 않는다**.

- 업로드·덮어쓰기
- 이름 변경
- 이동·복사
- 삭제
- 원격 폴더 생성
- 북마크·카테고리·편집 등 로컬 원본 전용 작업

다운로드된 사본은 받는 사용자의 로컬 파일이므로 이후 자유롭게 관리할 수 있다. 단, 사본 변경이 공유 원본에 반영되지는 않는다.

## 3. 목표와 비목표

### 3.1 목표

1. 폴더 선택 후 공유 시작까지 기존 앱 흐름에서 두세 동작으로 완료한다.
2. 받는 사용자가 주변 공유를 사이드바에서 바로 발견하게 한다.
3. 원격 항목과 로컬 파일을 구분해 실수로 로컬 파일 작업을 적용하지 않게 한다.
4. 이미지가 많아도 화면에 보이는 썸네일부터 불러와 UI를 막지 않는다.
5. 피어 오프라인·파일 변경·전송 실패를 크래시 없이 처리한다.

### 3.2 비목표(MVP)

- 인터넷상의 불특정 다수를 위한 공개 디렉터리
- 계정·팔로우·피드·댓글·좋아요
- 중앙 검색·추천·신고·관리자 기능
- 양방향 동기화 또는 받는 사용자의 업로드
- 하위 폴더 트리 탐색
- 오프라인 피어의 파일 대신 보관해 주는 중계 저장소
- 대량 폴더의 자동 전체 다운로드

## 4. 사용자 경험

### 4.1 공유하는 사람

1. 기존 사이드바에서 로컬 폴더를 연다.
2. 컨텍스트 메뉴 또는 파일 메뉴에서 **“이 폴더 P2P 공유…”**를 선택한다.
3. 공유 범위와 읽기 전용 공개를 확인하고 **공유 시작**을 누른다.
4. 사이드바의 **네트워크 공유** 섹션에 해당 폴더가 “이 Mac · 공유 중”으로 표시된다.
5. 공유를 중지하면 새 연결과 추가 다운로드를 받을 수 없다.

공유 시작 확인 문구에는 다음을 명시한다.

- 선택한 폴더의 직속 이미지만 공개된다는 점
- 같은 네트워크의 사용자가 읽고 다운로드할 수 있다는 점
- 원격 사용자가 원본을 수정할 수는 없다는 점
- 앱이나 공유를 종료하면 피어가 더 이상 파일을 받을 수 없다는 점

### 4.2 받는 사람

1. 사이드바 아래쪽 **네트워크 공유** 섹션에서 주변 공유 폴더를 확인한다.
2. 폴더를 선택하면 우측에 파일명·썸네일·이미지 수가 표시된다.
3. 하나 이상의 이미지를 선택하고 **다운로드**를 누른다.
4. 저장할 로컬 폴더를 선택하면 순차적으로 원본을 받는다.
5. 완료 후 저장 폴더를 Finder에서 열 수 있다.

### 4.3 원격 화면에서 제공하는 동작

| 동작 | 제공 여부 | 비고 |
|---|---|---|
| 이미지 선택·다중 선택 | 제공 | 다운로드 대상 선택 |
| 썸네일 보기 | 제공 | 보이는 항목 우선 |
| 선택 항목 다운로드 | 제공 | 저장 폴더 선택 |
| 새로고침 | 제공 | 최신 manifest 재요청 |
| 공유자·이미지 수·연결 상태 보기 | 제공 | 상단 요약 영역 |
| 업로드·삭제·이름 변경·이동 | 미제공 | 메뉴와 단축키 모두 비활성화 |
| 드래그 앤 드롭으로 원격 폴더에 파일 넣기 | 미제공 | 드롭 대상으로 등록하지 않음 |
| 로컬 북마크·카테고리 지정 | 미제공(MVP) | 다운로드 후 로컬 사본에 적용 |
| 원격 편집·비교 | 미제공(MVP) | 후속 단계에서 명확한 사본 정책과 함께 검토 |

## 5. 화면 설계

### 5.1 사이드바

기존 로컬 폴더 트리 아래에 별도 섹션을 추가한다.

```text
즐겨찾기
  북마크

폴더
  사진
  작업

네트워크 공유
  여행 사진          42
  제품 레퍼런스     128    · 이 Mac
  스튜디오 원본      —     · 오프라인
```

각 원격 행은 다음을 표시한다.

- 공유 폴더 이름
- 이미지 수(확인 전이나 오프라인이면 `—`)
- 공유한 Mac 이름 또는 “이 Mac”
- 온라인·연결 중·오프라인 상태
- 네트워크 폴더 아이콘(로컬 폴더와 시각적으로 구분)

로컬 `FolderNode`를 재사용해 원격 폴더를 흉내 내지 않는다. 원격 행은 별도 descriptor를 사용하며 절대 경로를 갖지 않는다.

### 5.2 원격 콘텐츠 영역

```text
┌──────────────────────────────────────────────────┐
│ 여행 사진                    [ ↓ 다운로드 ]       │
│ 민수의 Mac · 이미지 42개 · 읽기 전용              │
├──────────────────────────────────────────────────┤
│  [썸네일]      [썸네일]      [썸네일]             │
│  IMG_001.jpg   IMG_002.jpg   IMG_003.jpg          │
│                                                  │
│  [썸네일]      [썸네일]      [썸네일]             │
└──────────────────────────────────────────────────┘
```

- 기존 카드·격자의 시각 언어를 유지한다.
- 상단에 **읽기 전용**을 항상 표시한다.
- 빈 폴더, 연결 중, 오프라인, 권한 거부를 서로 다른 빈 상태로 표현한다.
- 다운로드 중에는 선택 변경은 허용하되 중복 작업 시작은 막고, 현재 파일명과 완료/전체 수를 표시한다.
- 무한 스크롤 대신 기존 그리드 가상화와 명시적 새로고침을 사용한다.

### 5.3 키보드와 접근성

- 화살표·Cmd/Shift 선택·Cmd+A는 원격 목록에서도 선택 동작으로 지원한다.
- Delete, Enter 이름 변경 등 로컬 편집 단축키는 원격 모드에서 동작하지 않는다.
- VoiceOver는 공유 폴더·공유자·온라인 상태·파일명·다운로드 진행 상황을 읽는다.
- 모든 버튼에 표준 포커스 링과 명확한 레이블을 제공한다.

## 6. 정보 모델

원격 파일은 로컬 `ImageFile`과 분리한다. 로컬 URL을 요구하는 썸네일·파일 조작·Vision 코드에 가짜 URL을 전달하지 않기 위해서다.

```swift
RemoteShare
- id: UUID                 // 공유 세션 안의 불투명 식별자
- peerID: String           // 발견된 피어 식별자
- name: String             // 표시용 폴더 이름
- peerName: String         // 표시용 Mac 이름
- images: [RemoteImage]
- state: online | connecting | offline

RemoteImage
- id: UUID                 // 공유자가 발급한 불투명 파일 식별자
- name: String             // 파일명만, 경로 아님
- byteCount: Int64
- revision: String         // 수정 시 캐시 무효화용
```

원격 모델에는 다음을 저장하지 않는다.

- 공유자의 절대 경로
- 사용자 홈 디렉터리
- 등록된 다른 로컬 폴더 정보
- 원격 파일을 가리키는 임의 `file://` URL

다운로드가 완료된 시점에만 받는 Mac의 로컬 URL이 생긴다.

## 7. 아키텍처

### 7.1 구성 요소

```text
SidebarViewController
  └─ 네트워크 공유 행 표시·선택
             │ delegate
             ▼
MainWindowController (Feature 중재)
  ├─ 로컬 폴더 모드
  ├─ 원격 공유 모드
  └─ 원격 요청의 세대 관리·취소
             │
             ▼
RemoteShareViewController
  ├─ 원격 이미지 그리드
  └─ 다운로드 진행 표시
             │
             ▼
LocalShareService
  ├─ Bonjour advertise / browse
  ├─ 피어 연결·요청 취소
  ├─ manifest / thumbnail / file
  └─ 공유 루트와 파일 ID 대응표
             │
             ▼
RemoteDownloadStore
  ├─ 수신 데이터 검증
  ├─ 임시 파일·원자적 저장
  └─ 파일명 충돌 처리
```

### 7.2 의존 방향

- UI → Service → Model 방향을 유지한다.
- 네트워크 프레임워크 타입이 Model이나 Sidebar에 새지 않게 한다.
- Service는 AppKit 창이나 ViewController를 직접 참조하지 않는다.
- UI 콜백은 메인 스레드에서 전달하고, 열거·썸네일 생성·전송·디스크 저장은 백그라운드에서 수행한다.

### 7.3 화면 상태

`MainWindowController`에 원격 공유 모드를 추가하되, 다음 상태는 단일 소유자만 둔다.

| 상태 | 소유자 | 수명 |
|---|---|---|
| 현재 선택 원격 공유 | MainWindowController | 화면 전환까지 |
| 발견된 피어·공유 목록 | LocalShareService | 탐색 중 |
| 현재 원격 이미지 목록 | RemoteShareViewController | 선택 공유 동안 |
| 썸네일 캐시 | 원격 캐시 저장소 | 세션 또는 디스크 LRU |
| 다운로드 진행 상태 | RemoteShareViewController | 작업 완료·취소까지 |
| 사용자가 공유 중인 로컬 루트 | LocalShareService + 설정 | 사용자가 중지할 때까지 |

폴더 전환 시 요청 generation을 올려 이전 피어의 늦은 응답이 새 화면을 덮지 못하게 한다. 로컬 폴더·북마크·카테고리로 이동할 때도 원격 요청을 취소하거나 응답을 폐기한다.

## 8. 네트워크 프로토콜

### 8.1 발견과 전송

- 발견: Bonjour `_jena-image._tcp`
- 전송: Network.framework의 피어 간 직접 연결
- 발견·연결은 사용자가 네트워크 공유 기능을 사용할 때 시작한다.
- macOS 로컬 네트워크 권한 설명과 Bonjour 서비스 선언을 추가한다.

### 8.2 읽기 전용 명령

| 명령 | 입력 | 출력 |
|---|---|---|
| `manifest` | 프로토콜 버전 | 공유 폴더·파일 ID·이름·크기·revision |
| `thumbnail` | shareID, fileID, revision, 크기 단계 | 썸네일 바이너리 |
| `file` | shareID, fileID, revision | 원본 바이너리 |
| `cancel` | requestID | 진행 중 전송 취소 |
| `error` | 안전한 오류 코드 | 사용자에게 표시 가능한 실패 정보 |

쓰기·삭제·경로 탐색 명령은 정의하지 않는다. 클라이언트는 파일 경로가 아니라 공유자가 발급한 ID로만 요청한다.

### 8.3 프레이밍과 검증

- 버전이 있는 길이 기반 프레임을 사용한다.
- JSON 헤더와 바이너리 payload를 분리해 원본을 Base64로 부풀리지 않는다.
- 헤더·manifest 항목 수·썸네일·원본 크기에 상한을 둔다.
- 수신한 길이가 선언된 길이와 같은지 확인한다.
- 원본에는 content digest를 포함하고 저장 전에 검증한다.
- 하나의 연결에 과도한 동시 요청을 몰아넣지 않고 backpressure를 적용한다.
- 다운로드는 기본 순차 처리로 시작해 메모리 사용을 제한한다.

## 9. 파일과 캐시 정책

### 9.1 공유 원본 보호

- 공유자는 manifest를 만들 때만 지원 확장자를 열거한다.
- 파일 ID와 로컬 URL 대응표는 공유하는 Mac 안에만 둔다.
- 요청받은 ID가 현재 공유 루트에 없으면 거부한다.
- 심볼릭 링크가 공유 루트 밖을 가리키면 제외한다.
- 파일이 목록 생성 후 삭제·변경되면 전송을 중단하고 revision 오류를 반환한다.

### 9.2 썸네일

- 원격 썸네일 키는 `(shareID, fileID, revision, pixelSize)`다.
- 보이는 셀 → 앞뒤 제한 범위 선로드 순으로 요청한다.
- 셀이 재사용되거나 공유를 전환하면 이전 요청을 취소하고 ID를 다시 확인한다.
- 기존 로컬 `ThumbnailProvider`에 가짜 원격 URL을 넣지 않는다.
- MVP는 메모리 캐시로 시작하고, 디스크 LRU 캐시는 사용량을 본 뒤 추가한다.

### 9.3 다운로드

- 사용자가 저장 폴더를 고른 뒤 선택한 파일만 받는다.
- 수신 중 파일은 `.part` 등 임시 이름으로 둔다.
- 길이·digest 검증을 통과한 뒤 원자적으로 최종 파일명으로 이동한다.
- 원격 파일명을 그대로 경로에 결합하지 않고 마지막 구성 요소와 금지 문자를 검증한다.
- 같은 이름이 있으면 기본적으로 `이름 2.ext` 형식으로 보존하며 자동 덮어쓰지 않는다.
- 실패한 임시 파일은 정리하고 완료 목록에 포함하지 않는다.
- 다운로드 캐시/사본을 기존 루트 폴더·북마크·카테고리에 자동 등록하지 않는다.

## 10. 개인정보·보안·신뢰

MVP는 **신뢰하는 같은 네트워크에서 민감하지 않은 이미지를 공유하는 용도**로 명확히 제한한다.

기본 보호 장치는 다음과 같다.

- 공유 기본값 off
- 폴더별 명시적 공개
- 읽기 전용 명령만 제공
- 불투명 ID 기반 요청
- 경로·절대 위치 비공개
- 메시지 크기와 전송량 제한
- 로컬 네트워크 사용 목적을 권한 문구에 표시

다만 Bonjour로 발견된다는 사실이 피어 신뢰를 의미하지는 않는다. 또한 MVP의 로컬 직접 전송만으로는 같은 네트워크의 모든 공격을 막지 못한다. **인터넷 공유 또는 공개 커뮤니티로 확장하기 전에** 다음을 별도 설계·구현해야 한다.

- 피어 인증(짧은 연결 코드 또는 호스트 승인)
- 전송 암호화와 신원 검증
- 악성·불법 콘텐츠에 대한 제품 정책
- 속도 제한·악용 방지
- 초대 링크와 NAT 연결 실패에 대한 명확한 UX

## 11. 오류와 빈 상태

| 상황 | 표현·동작 |
|---|---|
| 주변 공유 없음 | “같은 네트워크에서 공유 중인 폴더가 없습니다” |
| 로컬 네트워크 권한 거부 | 발견 불가 이유와 시스템 설정 이동 안내 |
| 피어 오프라인 | 마지막 목록은 흐리게 표시하고 새 요청 중단 |
| 공유 중지 | “공유가 종료되었습니다” 후 새로고침 |
| 파일 삭제·revision 변경 | 해당 항목만 실패 처리하고 manifest 갱신 제안 |
| 일부 다운로드 실패 | 성공 파일은 유지, 실패 수와 재시도 동작 표시 |
| 손상되거나 길이가 다른 데이터 | 임시 파일 삭제, 완료 처리 금지 |
| 앱 종료·화면 전환 | 요청 취소, 미완료 파일은 자동 완료로 표시하지 않음 |

오류 메시지에 공유자의 로컬 경로나 낮은 수준 네트워크 주소를 노출하지 않는다.

## 12. 단계별 구현 계획

### Phase 1 — 로컬 네트워크 MVP

1. 원격 모델·읽기 전용 프로토콜·프레임 검증 추가
2. 단일 폴더 공유 시작/중지와 Bonjour 발견 추가
3. 사이드바 네트워크 섹션과 원격 전용 그리드 추가
4. manifest·보이는 썸네일 로딩 추가
5. 선택 이미지 순차 다운로드·충돌 방지·오류 상태 추가
6. 원격 모드에서 로컬 파일 변경 메뉴·단축키 차단
7. 단위 테스트와 두 Mac 간 수동 검증

### Phase 2 — 사용성·신뢰 강화

- 연결 코드 또는 호스트 승인
- 전송 취소·재시도·이어받기
- 하위 폴더 탐색과 선택적 재귀 공유
- 원격 디스크 썸네일 캐시
- 다운로드 후 읽기 전용 미리보기
- 대용량 파일 스트리밍과 digest 검증 강화

### Phase 3 — 인터넷 직접 연결(별도 기술 검증)

- 초대 정보 교환
- NAT 유형별 연결 가능성 검증
- 외부 STUN 또는 수동 포트포워딩 정책 결정
- 인증·암호화·속도 제한
- 연결 불가 환경에서 중계 없음 원칙에 따른 명확한 실패 안내

## 13. 테스트 계획

### 13.1 단위 테스트

- 프레임 분할 수신·연속 수신·불완전 데이터·최대 크기 초과
- manifest 버전 불일치와 손상 데이터 거부
- 지원 확장자 필터링
- 다른 피어의 같은 파일명/파일 ID 충돌 방지
- revision 변경 시 이전 캐시·응답 폐기
- 공유 루트 밖 심볼릭 링크와 미공유 파일 ID 요청 거부
- 길이·digest 불일치 시 최종 파일 미생성
- 파일명 충돌 시 덮어쓰지 않고 새 이름 생성
- 취소된 요청의 늦은 응답이 화면을 바꾸지 않음

### 13.2 UI 테스트

- 원격 공유 선택 시 제목·목록·이미지 수가 함께 갱신됨
- 원격 모드에 업로드·삭제·이동·이름 변경·붙여넣기가 없음
- 원격 항목이 로컬 북마크·카테고리·유사 이미지 후보로 새지 않음
- 빈 공유·오프라인·권한 거부 상태가 구분됨
- 다중 선택 다운로드와 진행/완료/부분 실패 표시
- 다른 로컬 폴더로 빠르게 전환필 때 늦은 manifest가 표시되지 않음

### 13.3 두 Mac 수동 검증

- 같은 Wi-Fi에서 한쪽이 공유 시작하면 다른쪽 사이드바에 나타남
- 공유 폴더 외 파일과 절대 경로가 보이지 않음
- 받는 쪽에서 원본을 변경·삭제·업로드할 방법이 없음
- 선택한 파일만 저장 폴더에 다운로드됨
- 전송 중 공유 중지·Wi-Fi 끊김·상대 앱 종료 시 크래시 없이 실패 처리됨
- 같은 파일명이 있어도 기존 로컬 파일을 덮어쓰지 않음

## 14. MVP 완료 기준

- [ ] 사용자가 선택한 한 폴더만 명시적으로 공유 시작·중지할 수 있다.
- [ ] 같은 네트워크의 다른 Mac에서 공유 폴더가 사이드바에 표시된다.
- [ ] 원격 이미지 목록과 썸네일을 볼 수 있다.
- [ ] 선택한 이미지를 로컬 저장 폴더에 다운로드할 수 있다.
- [ ] 원격 업로드·수정·삭제 명령과 UI가 존재하지 않는다.
- [ ] 공유자의 절대 경로와 미선택 폴더가 노출되지 않는다.
- [ ] 오프라인·전송 실패·파일 변경을 크래시 없이 처리한다.
- [ ] 단위 테스트, UI 테스트, 두 Mac 수동 검증을 통과한다.
- [ ] 인터넷 연결·인증·암호화가 MVP에 포함되지 않는다는 한계를 사용자 문서에 명시한다.

## 15. 구현 전 확인이 필요한 후속 결정

MVP 착수 자체를 막지는 않지만, Phase 2 이전에 다음을 제품 결정으로 확정한다.

1. 같은 네트워크의 모든 사용자에게 바로 공개할지, 연결 코드/승인을 기본으로 할지
2. 공유 설정을 앱 재시작 후 자동 복원할지
3. 허용할 최대 파일 크기와 동시 다운로드 수
4. 다운로드된 사본의 기본 저장 위치를 고정할지 매번 선택하게 할지
5. 공개 인터넷 커뮤니티가 진짜 목표인지, 신뢰하는 소규모 작업 공유가 목표인지
